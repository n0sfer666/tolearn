# Архитектура для агента

Полная версия с обоснованиями — [docs/architecture.md](../docs/architecture.md).
Здесь — рабочая карта: куда класть код и чего нельзя делать.

## Дерево

```
core/       Rust: формат программы, библиотека, пакет, поиск
runner/     Rust: исполнение check-команд       (зависит от core)
offline/    Rust: загрузка, архивация, кэш      (ни от чего не зависит)
provider/   Rust: настройки LLM, ключ, проверка (зависит от core, runner)
generate/   Rust: генерация программы и этапов  (зависит от core, offline, provider)
gestures/   Rust: нативный жест «назад»         (ни от чего не зависит)
cli/        Rust: tolearn export|pack|unpack|new|next (зависит от core, offline, provider, generate)
app/        Tauri 2: IPC, окна, пререндер       (зависит от нижних слоёв)
ui/         Astro + Solid                       (общается только через IPC)
docs/       решения, спецификации, контракты
examples/   эталонная программа, она же фикстура
fixtures/   ветки, которых нет в эталоне: валидные и битые документы
```

## Направление зависимостей — только вниз

Нарушение — это не «некрасиво», а сломанный CI: `cli` обязан работать в
headless-окружении без GUI.

| Крейт | Не имеет права знать про |
|---|---|
| `core` | Tauri, файловый диалог, UI, сеть, ФС-специфику приложения |
| `offline` | Tauri, WebView, UI |
| `runner` | Tauri, UI |
| `provider` | Tauri, UI, программу и её файлы |
| `generate` | Tauri, WebView, UI: схемы и события шагов — трейты, окно подставляет `app` |
| `cli` | Tauri, WebView, UI: схемы без окна остаются исходником Mermaid |
| `ui` | что угодно, кроме IPC-контракта |

`unsafe` разрешён ровно в одном крейте — `gestures`, где включается нативный жест
«назад» у вебвью. Везде остальном `unsafe_code = "forbid"` из `[workspace.lints]`;
крейт со своими `[lints]` обязан объявить `unsafe_code` явно, иначе падает S01.

Правило закреплено гейтом `cli/tests/layering.rs` (S01). Он падает на:

- зависимости вверх или вбок по дереву — включая объявленные в
  `[target.'cfg(...)'.dependencies]` и переименованные через `package = "..."`;
- имя оболочки (`tauri`, `wry`, `webkit`, `objc`) в зависимостях `core`,
  `runner`, `offline`, `provider`, `generate`, `cli` — прямых **и** транзитивных, по `Cargo.lock`;
- расхождение списка крейтов с блоком «Структура» в
  [docs/architecture.md](../docs/architecture.md#структура) — документ читается
  тестом, а не пересказывается в нём;
- крейт, не наследующий `[lints] workspace = true` и поля `version`, `edition`,
  `rust-version`, `license`, `repository`, `publish` из `[workspace.package]`.

Переименования гейт разворачивает в настоящее имя пакета обоими способами:
`package = "..."` у крейта и `package = "..."` в корневом
`[workspace.dependencies]` при записи вида `alias.workspace = true`. Граф лока
ключуется парой «имя + версия», иначе два разных срока жизни одного крейта
(`winnow 0.7` и `winnow 1.0` уже в локе) схлопывались бы в одну вершину и рёбра
младшей версии терялись. Ребро лока, не ведущее ни в один `[[package]]`, — тоже
падение: гейт не имеет права молча недосчитать путь.

`windows-sys` в запрещённые имена **не** входит: это Win32 FFI, а не оболочка, и
он понадобится `runner` для убийства дерева процессов на Windows: на unix S16
обошёлся `process_group(0)` + внешним `kill -9 -<pgid>`, потому что `libc::killpg`
— `unsafe`, а воркспейс держит `unsafe_code = "forbid"`.

Гейт живёт в `cli`, потому что именно `cli` по
[architecture.md](../docs/architecture.md#структура) существует ради прогона
слоёв в CI без GUI; отдельного крейта под один тест не заводили — дерево крейтов
задано документом. Чтение источников вынесено в `cli/tests/sources/`: `manifest`
(`Cargo.toml`), `lockfile` (`Cargo.lock`), `document` (`docs/architecture.md`).

`cli/tests/repo/` — общий для всех гейтов доступ к файлам репозитория (`root`,
`read`); хелперы гейта схем разложены по ответственностям в `cli/tests/schema/`:
`corpus` (какие документы считаются корпусом), `programs` (обход каталогов
программ v2 с `children/`), `paths` (обход схемы), `instance` (обход документа),
`codes` (код ошибки валидатора), `fields` (чтение `docs/format.md`),
`yaml`. Хелпер, нужный одному гейту, живёт у него, а не в
`repo/`: два тест-таргета делят один `mod`, и функция, которую использует только
один из них, даёт `dead_code` — под `-D warnings` это падение сборки.

Следствие, которое проектируется заранее: `offline` объявляет трейт
`Prerenderer` (`url → HTML`). Заглушка «вернуть исходный HTML» живёт в `offline`
(S19), настоящая на WebView — в `app` (S37). Так `offline` остаётся без Tauri, а
пререндер — необязательным улучшением, а не условием работы загрузчика
([ADR-003](../docs/adr/003-offline-monolith.md)). С S95 приложение WebView-пререндер
не устанавливает: загрузчик до группы C никто не зовёт. ADR-023 отдаёт его
проверке источников (S115), а зеркало, `repo` и видео (S21–S23) ушли в S112.

Тот же приём в `generate`: сеть он проверяет через трейт `offline::reach::Reach`
(настоящий — `Ping`, HEAD с таймаутом), модель зовёт через трейт `Model`. До
модели доступ только через `online(reach, model)`: сначала отвечают все `HOSTS`,
иначе — `generate.offline` с хостом и причиной, и `Online` не создаётся. Тесты
подставляют заглушки обоих трейтов и считают вызовы модели.

Книгу `offline::book::find(source, wanted)` ищет в Open Library через тот же
`Source` загрузчика: по ISBN, если он есть, иначе по названию и автору. Запасного
поиска по названию при неудаче с ISBN нет. `Ok(None)` значит «не найдено»,
`BookError::Unreachable` — сбой сети с причиной, `Malformed` — ответ не
разобрался. Тесты работают на записанных ответах из `fixtures/openlibrary/`.

Источники, которые предложила модель, проверяет `generate::sources::Sources`
(источник, пререндер, `Store`, `<data>`, uuid программы, момент). `page(url)`
грузит страницу через `page::save` без подресурсов, кладёт сырой HTML в `Store`
(`kind: "page"`) и сразу вызывает `sweep` по бюджету, затем прогоняет читалку.
`book(wanted)` вызывает `offline::book::find`. Итог — `Outcome { checked_at,
verdict }`, где `Verdict` — `Passed(Verified { url, title, text })` / `Passed(Book)`
или `Refused(причина)`. Итог пишется атомарно в
`<data>/cache/<uuid>/{pages,books}/<sha256 ключа>.json`, а повторный вызов в той же
программе читает его без запросов. Отказы «нет текста» и «книги нет» тоже
кэшируются. Сбой сети не кэшируется: он временный. Битый JSON в кэше считается
промахом, ошибка ввода-вывода — `generate.cache`. Модели идёт
`excerpt(text)`, это первые `PAGE_CHARS` = 8000 символов.

Картинку ищет `offline::commons::find(source, query)` в Wikimedia Commons: пять
файлов поисковой выдачи по рангу, лицензия и автор из `extmetadata`. Проходит
первый файл со свободной лицензией (CC0, PD, CC BY, CC BY-SA) и указанным
автором. Скачивается его миниатюра шириной 960 px, предел веса — 400 КБ.
Остальные исходы — `Found::Refused(причина)` или `Found::Missing`.
`Sources::image(query, caption)` превращает находку в `Illustration`: байты,
имя ассета по sha256 и готовый блок `image` с лицензией, атрибуцией и страницей
файла. Отказ, «не найдено» и сбой сети дают `Verdict::Refused`, кэша у картинок
нет. Wikimedia без `User-Agent` отвечает 403, поэтому клиент `offline::net`
представляется как `tolearn/<версия>`.

Схему рисует `generate::diagram::draw(painter, mermaid)` через трейт `Painter`.
Ответ окна проходит две проверки: он начинается с `<svg`, и его пропускает
`core::package::svg::check`, та же проверка, что у импорта (S102). Прошедший
ответ становится `Diagram::Drawn`: `Illustration` с SVG-ассетом по sha256 и
блоком `diagram`, где `text` — исходник Mermaid. Любой отказ, включая таймаут и
сломанную разметку, даёт `Diagram::Source`: блок `code` с `lang: mermaid` и
причину. `Painter` реализует `app::mermaid::Mermaid`. Он открывает скрытое окно
`mermaid-N` на своей схеме `tolearn-mermaid://` (на Windows —
`http://tolearn-mermaid.localhost/`), и плагин отдаёт этому окну три файла из
бинарника: страницу, `draw.js` и `@mermaid-js/tiny`. Заголовок
`default-src 'none'; script-src 'self'` не выпускает окно в сеть, а
`on_navigation` не даёт ему уйти со своей схемы. Исходник передаётся в `#`
адреса. Mermaid работает с `securityLevel: strict` и без HTML-меток, результат
снимается через `XMLSerializer` и забирается опросом `eval_with_callback`, как у
S37. Общие для обоих окон `on_main` и `answer` лежат в `app/src/hidden.rs`.

Карту строит `generate::plan`. `plan(online, request)` просит модель о карте
всей программы, а `expand(online, request, part, depth)` — о карте подпрограммы
с целью и часами её строки у родителя. Шаг один и тот же. Ответ — объект JSON
(ограда и текст вокруг срезаются): `title`, `slug`, `goal`, `volatility`,
`stages` или `children`. `plan::check(plan, depth)` возвращает список `Flaw`
по ADR-013:
- этап — 2–4 ч, `id` — slug без повторов;
- лист — не больше 70 ч и 25 этапов;
- строка подпрограммы — 1–70 ч;
- узел на уровне `MAX_DEPTH` — нарушение.

Нечитаемый ответ — тоже `Flaw`. Нарушения уходят модели вместе с её прошлым
ответом, до `REPAIRS` = 3 кругов. Не сошлось — `GenerateError::Unrepaired` с
перечнем.

## Владение данными

| Данные | Владелец | Где лежит |
|---|---|---|
| офлайн-хранилище v1 (S18–S24) | больше никто: не читается и не удаляется (ADR-022) | `<app-data>/offline/` |
| черновик генерации v1 (S65) | больше никто: не читается и не удаляется (ADR-022) | `<app-data>/draft/` |
| бандл v1, приехавший архивом | больше никто: не читается и не удаляется (S107) | `<app-data>/unpacked/<roadmap-id>/` |
| программа v2: карта, этапы, ассеты | генерация и импорт | `<app-data>/programs/<uuid>/` |
| пользовательское v2 | приложение | `<app-data>/state/<uuid>/` |
| сырой HTML источников и итоги их проверки | генерация (S115); стирается без потерь | `<app-data>/cache/objects/`, `<app-data>/cache/index.sqlite`, `<app-data>/cache/<uuid>/` |

`<app-data>` — это `~/.local/share/tolearn` (или `$XDG_DATA_HOME/tolearn`), а
настройки живут отдельно: `settings.yaml` и `provider.yaml` лежат в
`~/.config/tolearn` (или `$XDG_CONFIG_HOME/tolearn`); реестр v1 `registry.yaml`
там же приложение переносит, но не читает (S107). Первый запуск
переносит туда содержимое старого `~/Library/Application Support/dev.tolearn.app`,
если оно осталось; то, что уже есть на новом месте, переезд не трогает
(`app/src/ipc/layout.rs`).

Программа v2 живёт в библиотеке: содержимое
`<app-data>/programs/<uuid>/` пишут только генерация и импорт, пользовательское —
`<app-data>/state/<uuid>/` ([ADR-020](../docs/adr/020-v2-program-library.md)).
`id` блока этапа — `core::block` (S97): первые 8 hex sha256 текста,
повторы в этапе — `-2`, `-3`.

## Чтение программы

- Формат v2 — две схемы `tolearn/program/1` и `tolearn/stage/1` в
  [docs/schemas/](../docs/schemas/) (JSON Schema draft 2020-12, без внешних
  `$ref`, `additionalProperties: false` на каждом объекте), роли полей —
  [docs/format.md](../docs/format.md), эталон — `examples/chiptune/`, корпус —
  [fixtures/v2/](../fixtures/README.md) (S98). Гейт схем
  (`cli/tests/schemas.rs`) гоняет виды документа списком `KINDS`.
- Чтение v2 — `tolearn_core::program` (S99): `parse`, `load(каталог) → Tree`,
  `validate(&Tree) → Vec<Violation>`; этап — `tolearn_core::stage`, блок —
  `tolearn_core::block`. `load` отказывает только на нечитаемом или
  неразобранном файле (`LoadError` с файлом и строкой), остальное собирает
  `validate` — все нарушения, а не первое. Строка карты без файла или каталога —
  ещё не сгенерированная часть, не ошибка; глубже третьего уровня `load` не
  спускается.
- Библиотека v2 — `tolearn_core::library` (S100) над `<data>/programs/`:
  `list` не падает на битом каталоге, а кладёт в строку причину (`Refusal`);
  `open(uuid)` сверяет UUID с шаблоном до того, как он станет путём;
  `install(источник)` читает источник по S99 и копирует только прочитанное —
  во временный `.<uuid>.<pid>.tmp` рядом, затем `rename`. Скрытые записи
  каталога — чужие временные файлы, список их не видит. Занятый UUID — отказ
  `library.taken`: копию решает импорт (S102). Ничего, кроме `programs/`,
  библиотека в `<data>` не открывает.
- Пакет v2 — `tolearn_core::package` (S101): `pack(каталог)` читает программу
  через `library::read` (та же проверка S99, что у установки) и кладёт в zip
  ровно `Tree::files()` — список, по которому копирует и `install`. Манифест
  `tolearn/package/1` с sha256 каждого файла пишется последней записью; время,
  права и порядок записей фиксированы, поэтому пакет одной программы всегда один
  и тот же по байтам. Формат — [docs/format.md](../docs/format.md#пакет-tolearn).
- Импорт v2 — `package::import` и `package::unpack` (S102) над одной проверкой
  `verify::open`: `archive::unzip` (защиты S48 без поиска `roadmap.yaml`, только
  zip) во временный скрытый каталог (`package/scratch.rs`, `create_dir` с
  номером из `ticket()`), манифест, файлы против манифеста и sha256, S99,
  лишние записи манифеста, SVG через quick-xml. Отказ — `UnpackError` с кодом и
  путём внутри пакета. Пересечение любого UUID дерева (`Tree::uuids()`: корни и
  строки карт) с библиотекой — `renew`: новые UUID v4 всему дереву заменой по
  span узла YAML (`program::places`) и переименованием `children/` снизу вверх,
  перечитывание, затем `install`. До группы G совпадение UUID всегда даёт копию.
- Экраны v2 (S103) читают библиотеку командами `library`, `import_package`,
  `node`, `stage` (`app/src/ipc/{shelf,reading,picture}.rs`). Узел адресуется
  парой «программа + UUID подпрограммы», пустой узел — корень. Картинка и схема
  едут в UI как `data:` URI: `library::asset` отдаёт только файл из
  `Tree::files()` и только если канонический путь остался в каталоге программы
  (симлинк наружу), иначе `library.foreign`; CSP не менялся. Отсутствующие
  узел и этап — `node.absent`, `stage.absent`. До `package::import`
  приложение отсекает не-пакеты: каталог программы — `package.folder`, каталог
  или архив v1 (`roadmap.yaml`/`roadmap.json`, `.zip`, `.gz`, `.tgz`) —
  `package.v1` (ADR-016), прочее — `package.foreign`.
- Карта новой программы (S119) — команды `plan_program` и `revise_plan`
  (`app/src/ipc/{planned,planning,voiced}.rs`). До «Начать» карту держит UI:
  переделка присылает прежнюю карту и уточнение, `generate::plan::revise`
  кладёт обе в промпт, на диск не пишется ни байта. Порядок: пустой запрос или
  уточнение — `plan.empty`, провайдер и ключ, `Context::reach()` (в тестах —
  `with_reach`), `generate::online`, модель через `Voiced` с записью в журнал
  («Карта программы», «Переделка карты»). Ответ — карта и сумма часов
  `Plan::hours()`.
- Этап: источники и текст (S120) — `generate::stage::{gather, text}`.
  `gather` просит у модели книги, страницы и картинки по карте, месту этапа
  (`Place`) и классу `volatility` и проверяет каждый через `Sources`;
  отвергнутые и нечитаемый ответ уходят одним запросом замены, отказ замены —
  источник выброшен (`Gathered::dropped`). `text` — один вызов: источники под
  id `b1`, `p1`, `i1`, страница — `excerpt`. Этап собирает код: id блоков —
  `block::ids`, `c1…`, `a1…`, `q1…` по порядку, id и название — из строки
  карты, картинка — поля `Illustration`. Ссылка мимо проверенного — `Flaw`, а
  не ошибка: чинит S121. `terms` и `tools` живут в `Draft`, в этап не пишутся.
  Диаграмма до S122 без `asset` — `stage::check` даёт `BlockWithoutAsset`.
- Этап: инварианты и починка (S121) — `generate::stage::compose` поверх
  `text`. Часы строки вне 2–4 — `generate.stage-hours` без вызова модели.
  `stage::invariants` проверяет формат, длину теории, число терминов, практику,
  вопросы и один инструмент в первом этапе; пороги — константы `stage::*`,
  числа в ADR-023. Каждый `Flaw` указывает на часть этапа (`Part`). В починку
  уходит сырой JSON только этих частей, ответ вклеивается в сырой ответ
  (`raw` → `patch` → `answer::build`), и `id` целых блоков не меняются: это хеш
  текста. До трёх кругов, затем `generate.unrepaired`.
- Сборка и запись этапа (S122) — `generate::start::start(Kit, request, plan)`:
  карта с детьми разворачивается до листа (`plan::expand`), затем источники,
  текст с починкой, схемы через `diagram::Painter`, сборка в
  `cache/<uuid>/build/` и `Library::install`. Шаги — `Step`, наблюдатель —
  `Progress::{began, ended}`, отмена — `Stop` в `Kit`: флаг смотрится между
  шагами и перед каждой проверкой источника, перед `install` запечатывается
  (`Stop::seal`), и поздняя отмена отказывает. В приложении — команды
  `start_program {request, level, plan} → {program}` и
  `cancel_generation → {cancelled}` (`app/src/ipc/{started,running,tools,
  announced,wired}.rs`). `Context` несёт `Tools` (источник страниц, пререндер,
  художник схем, глашатай шагов) и `Running` — одна генерация за раз, иначе
  `generate.busy`. `wired` подставляет окно Mermaid, пререндер WebView и
  `emit("generation-step", {step, state, round})`; без окна схема остаётся
  кодом (`Unpainted`), пререндер — `AsFetched`. Общая команда `command` async:
  вызов уходит в `spawn_blocking`, главный поток свободен для `hidden::on_main`.
  У `start_program` уровень обязателен (`plan.empty`), у `plan_program` — нет:
  экран S127 требует уровень до «Начать».
- Журнал запросов (S123, [ADR-024](../docs/adr/024-request-ledger.md)) —
  `generate::ledger`. `Online` несёт `Tally`: `ask(step, prompt)` и
  `again(step, round, prompt)` пишут запись на каждый вызов модели, отменённый
  и отказавший тоже (шаг, круг, мс, модель, `provider::Tokens`, `ok`),
  `Sources` через `counted(tally)` — на каждую проверку страницы, книги и
  картинки мимо кэша. Токенов нет — `None`, в тексте «нет данных». `start`
  помечает записи программой, этапом (`Tally::stamp`) и моментом (`date`) и в
  шаге «Запись» дописывает их в `cache/<корень>/ledger.jsonl`. Записи карты до
  «Начать» держит управляемое состояние приложения `ipc::Ledger`: удачная
  новая карта заменяет накопленное (`Tally::replace`), отказ и `revise_plan`
  дописывают, `start_program` забирает, а при отказе возвращает вместе с
  записями попытки (`Tally::release`). Итог — `Total::of` и `Total::stage`,
  без IPC. Отказ S124/S125 журнал программы не стирает.
- Развилка и следующий этап (S124) — `generate::fork`. `known` и `propose`
  отдают `Fork { variants }`: вариант 0 — следующая строка карты, за ним до
  двух альтернатив. `take(Kit, After, choice)` ставит выбранную строку на место
  следующей и пишет этап сборкой и подменой: копия дерева (`Library::copy`) в
  `cache/<корень>/build/`, лист по префиксу ветки (`build::staged`),
  `Library::replace`. `After {program, node, stage}`: `node` — лист, в котором
  пройден этап. Развилка кэшируется в `cache/<узел>/fork/`, отказы — `NextError`
  (`next.*`) до модели. В приложении — `fork` и `take_next`
  (`app/src/ipc/{forked,forking,kitted,clock}.rs`); `kitted` собирает `Kit`
  для `start_program` и `take_next`. Конвейер этапа (источники → текст →
  схемы) у старта и следующего этапа общий — `generate::build::build(kit,
  place) -> Built`, свой у каждого только шаг записи.
- Перегенерация этапа (S125) — `generate::regenerate::regenerate(kit,
  After)`: `build::rebuild` берёт набор источников из
  `cache/<лист>/gathered/<этап>` (его сохраняет каждая сборка, `build::saved`:
  выдержки страниц, строка карты, картинки файлами в `pictures/`; запись без
  гарантии, битый или чужой набор — промах) и пишет промпт с прежним текстом
  (`stage::recompose`, резерв `PREVIOUS_CHARS`). Поиск узла, строки карты и
  созданного этапа у развилки и перегенерации общий — `located`, его `Missing`
  каждый переводит в свои коды. Запись и финал у
  `take` и перегенерации общие: `build::swapped` (копия дерева, лист по
  префиксу, `sealed`, подмена) и `build::settled` (убрать `build/`, журнал).
  Отказы — `RegenerateError` (`regenerate.*`) до модели. В приложении —
  `regenerate_stage` (`app/src/ipc/regenerated.rs`).
- Генерация из CLI (S126, [ADR-025](../docs/adr/025-cli-generation.md)) —
  библиотека `tolearn_cli::run(argv, world)`: `World` — сеть (`Reach`),
  страницы (`Source`), хранилище ключа, каталоги настроек и данных
  приложения, поток шагов и момент; `World::real` собирает настоящие, тесты — подставные. `session/`:
  `Crew` (провайдер из `provider.yaml` или `--provider` через `provided`,
  ключ `Keychain::app()` — только у удалённого, язык из `settings.yaml`, `kitted` собирает `Kit` над
  `<data>/cache`), `Speaker` — модель с `Meter` токенов на каждый ответ,
  `Herald` — `Progress`, пишет строку шага в stderr, `Unpainted` — художник,
  который всегда отказывает, `position` — последний созданный этап,
  подпрограммы первыми, `apart` — отказ для каталога в хранилище
  приложения, `opened` — дерево записанной программы по uuid. `Places` и `places` переехали из `app` в
  `core::places`, `Keychain::app()` — в `provider`: у CLI и приложения один
  каталог настроек и одна запись ключа.
- Файлы написаны LLM: могут быть неполными, невалидными и содержать
  произвольный shell. Несгенерированная часть программы — нормальное состояние
  ([ADR-007](../docs/adr/007-incomplete-bundle.md),
  [ADR-013](../docs/adr/013-incremental-program-generation.md)), а не ошибка.
- Строгость входа держит парсер, а не только схема: дубль ключа — ошибка разбора
  (ловится на событиях, в готовом дереве его уже не видно), пустая строка там, где
  схема требует непустую, дата проверяется по форме и календарю. Связь между
  файлами — дело `validate`, у него видно всё дерево.
- Ни одна `check`-команда не выполняется без явного действия человека
  ([ADR-006](../docs/adr/006-human-verdict.md)).

## Слой YAML

`core/src/yaml/` — тонкий слой над `saphyr`: `Reader` ходит по документу с
сохранением пути поля (`practice.acceptance[0].id`), `ParseError` несёт код,
строку, колонку, путь и сообщение. Своих типов документов слой не знает, но
знает словарь, общий для всех: `text`, `optional_text`, `date`,
`number(minimum)`, `bounded`, `flag`, `choice` по таблице вариантов, `list`,
`texts`, `slug`, `uuid`. Разбор вида документа живёт у своего модуля:
`program::parse(&str)`, `stage::parse(&str)`. Коды слоя пинят
`core/tests/yaml_{document,values}.rs` на документах эталона.

- **Неизвестное значение `enum`** — ошибка: молча посчитать его чем-то другим
  нельзя.
- Ошибка несёт **машинный код** — `ParseFailure::code()`: `yaml.syntax`,
  `yaml.document-count`, `yaml.duplicate-key`, `yaml.empty`, `yaml.bad-date`,
  `yaml.missing-field`, `yaml.wrong-type`, `yaml.out-of-range`,
  `yaml.unknown-value`. UI и тесты ветвятся по коду, проза сообщения — для
  человека.
- Дубль ключа ловится на событиях парсера (`duplicates.rs`): в готовом дереве
  `saphyr` второе вхождение уже затёрло первое.
- Колонка у `saphyr` считается с нуля, строка — с единицы; `ParseError`
  нормализует обе к единице, потому что число едет человеку в сообщение.
- BOM снимается с начала источника до разбора: иначе он приклеивается к первому
  ключу и файл с видимым `schema:` падает с «поля нет».
- `core/src/date.rs` отвечает на один вопрос — «это дата `YYYY-MM-DD`,
  которая есть в календаре?»: месяц 1–12, день не больше длины месяца,
  29 февраля только в високосный год. Моментов RFC 3339 и арифметики дат в v2
  нет: их читал и считал только прогресс v1.

## Бюджеты

Пороги — в [architecture.md](../docs/architecture.md#бюджеты). Каждый обязан
быть закреплён тестом, который ломает сборку при превышении. Ужесточать по
замерам можно, ослаблять — нет: вместо ослабления режется функция.

## IPC

Контракт появляется в S25: команды объявляются в одном месте, типы для UI
генерируются оттуда же, рукописная команда мимо описания ломает тест. До S25
файла `api.md` в `.context/` нет намеренно — описывать нечего.
