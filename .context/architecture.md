# Архитектура для агента

Полная версия с обоснованиями — [docs/architecture.md](../docs/architecture.md).
Здесь — рабочая карта: куда класть код и чего нельзя делать.

## Дерево

```
core/       Rust: типы, парсинг, валидация, прогресс, статусы, протокол
runner/     Rust: исполнение check-команд       (зависит от core)
offline/    Rust: загрузка, архивация, кэш      (зависит от core)
cli/        Rust: tolearn validate|scan|exam    (зависит от core, runner, offline)
app/        Tauri 2: IPC, окна, пререндер       (зависит от core, runner, offline)
ui/         Astro + Solid                       (общается только через IPC)
docs/       решения, спецификации, контракты
examples/   эталонные бандлы, они же фикстуры
fixtures/   ветки, которых нет в эталоне: валидные и битые документы
```

## Направление зависимостей — только вниз

Нарушение — это не «некрасиво», а сломанный CI: `cli` обязан работать в
headless-окружении без GUI.

| Крейт | Не имеет права знать про |
|---|---|
| `core` | Tauri, файловый диалог, UI, сеть, ФС-специфику приложения |
| `offline` | Tauri, WebView, UI |
| `runner` | Tauri, UI |
| `ui` | что угодно, кроме IPC-контракта |

Правило закреплено гейтом `cli/tests/layering.rs` (S01). Он падает на:

- зависимости вверх или вбок по дереву — включая объявленные в
  `[target.'cfg(...)'.dependencies]` и переименованные через `package = "..."`;
- имя оболочки (`tauri`, `wry`, `webkit`, `objc`) в зависимостях `core`,
  `runner`, `offline`, `cli` — прямых **и** транзитивных, по `Cargo.lock`;
- расхождение списка крейтов с блоком «Структура» в
  [docs/architecture.md](../docs/architecture.md#структура) — документ читается
  тестом, а не пересказывается в нём;
- крейт, не наследующий `[lints] workspace = true` и поля `version`, `edition`,
  `rust-version`, `license`, `repository`, `publish` из `[workspace.package]`.

Переименования гейт разворачивает в настоящее имя пакета обоими способами:
`package = "..."` у крейта и `package = "..."` в корневом
`[workspace.dependencies]` при записи вида `alias.workspace = true`. Граф лока
ключуется парой «имя + версия», иначе два разных срока жизни одного крейта
(`winnow 0.7` и `winnow 1.0` уже в локе) схлопывались бы в одну вершину и рёбра
младшей версии терялись. Ребро лока, не ведущее ни в один `[[package]]`, — тоже
падение: гейт не имеет права молча недосчитать путь.

`windows-sys` в запрещённые имена **не** входит: это Win32 FFI, а не оболочка, и
он понадобится `runner` для убийства дерева процессов на Windows (S16).

Гейт живёт в `cli`, потому что именно `cli` по
[architecture.md](../docs/architecture.md#структура) существует ради прогона
слоёв в CI без GUI; отдельного крейта под один тест не заводили — дерево крейтов
задано документом. Чтение источников вынесено в `cli/tests/sources/`: `manifest`
(`Cargo.toml`), `lockfile` (`Cargo.lock`), `document` (`docs/architecture.md`).

`cli/tests/repo/` — общий для всех гейтов доступ к файлам репозитория (`root`,
`read`); хелперы гейта схем разложены по ответственностям в `cli/tests/schema/`:
`corpus` (какие документы считаются корпусом), `paths` (обход схемы), `instance`
(обход документа), `codes` (код ошибки валидатора), `fields` (чтение
`docs/fields.md`), `yaml`. Хелпер, нужный одному гейту, живёт у него, а не в
`repo/`: два тест-таргета делят один `mod`, и функция, которую использует только
один из них, даёт `dead_code` — под `-D warnings` это падение сборки.

Следствие, которое проектируется заранее: `offline` объявляет трейт
`Prerenderer` (`url → HTML`). Заглушка «вернуть исходный HTML» живёт в `offline`
(S19), настоящая на WebView — в `app` (S37). Так `offline` остаётся без Tauri, а
пререндер — необязательным улучшением, а не условием работы загрузчика
([ADR-003](../docs/adr/003-offline-monolith.md)).

## Владение данными

| Данные | Владелец | Где лежит |
|---|---|---|
| `roadmap.yaml`, `topics/*.yaml`, `examiner.md` | генератор (LLM) | папка бандла |
| `progress.yaml` | приложение | папка бандла + зеркало в app-data |
| конспекты | человек | `<app-data>/notes/` или внешний каталог |
| офлайн-кэш | приложение | `<app-data>/cache/` |

Приложение **не пишет** в файлы бандла, кроме `progress.yaml`
([ADR-009](../docs/adr/009-user-data-outside-bundle.md)). Перегенерация бандла —
штатный сценарий: обрабатывается слиянием по `id`, ничего пользовательского не
удаляется.

## Чтение бандла

- Читаем оба формата, и отдельного JSON-парсера для этого не понадобилось: JSON —
  подмножество YAML 1.2, `saphyr` разбирает его как есть. Парсеры S03/S04
  принимают строку и про формат не знают; равенство разбора двойников закреплено
  тестом `core/tests/json_twins.rs`. Бандл с 2026-07-27 приходит в **одном**
  формате (`json` по умолчанию, `yaml` по запросу), поэтому вся оставшаяся работа
  — выбор файла на входе, и она относится к S09, а не к парсерам.
- Разница между форматами видна только в диагностике на битом документе: `{"id": }`
  — не синтаксическая ошибка, а валидный YAML-поток со значением `null`, и
  ошибка приходит как `WrongType`. Это поведение пиннится тестом намеренно.
- Три независимо версионируемые схемы: `learning-roadmap/v1`,
  `learning-roadmap/topic/v1`, `learning-roadmap/progress/v1`. Несовпадение
  мажорных версий внутри одного бандла — ошибка импорта, не повод угадывать.
- Контракт схем — [docs/schemas/](../docs/schemas/) (JSON Schema draft 2020-12,
  без внешних `$ref`), роль каждого поля — [docs/fields.md](../docs/fields.md),
  корпус документов — [fixtures/](../fixtures/README.md). Схема строгая
  (`additionalProperties: false` на каждом объекте), парсер — мягкий: неизвестное
  поле не роняет разбор (S03). Строгость схемы — то, чем доказывается «схема
  описывает все поля эталона»; гейт S02 живёт в `cli/tests/schemas.rs`.
- Файлы написаны LLM: могут быть неполными, невалидными и содержать
  произвольный shell. Незавершённый бандл (`generated: false`) — нормальное
  состояние ([ADR-007](../docs/adr/007-incomplete-bundle.md)), а не ошибка.
- Строгость входа держит парсер, а не только схема: дубль ключа — ошибка разбора
  (ловится на событиях, в готовом дереве его уже не видно), пустая строка там, где
  схема требует непустую, дата и момент проверяются по форме. Связь двух значений
  (`est_hours` с `min > max`) — дело валидатора, у него виден весь бандл.
- Ни одна `check`-команда не выполняется без явного действия человека
  ([ADR-006](../docs/adr/006-human-verdict.md)).

## Запись прогресса

- `progress.yaml` — единственный файл бандла, в который приложение пишет. Запись
  идёт правкой исходного дерева документа (`core::progress::Document`), а не
  сериализацией типов: типизированный `Progress` — read-only вид для логики.
  Отсюда бесплатно берутся два требования — неизвестные ключи чужих версий
  остаются на месте, порядок тем не меняется.
- Формат вывода равен формату входа (`Format::{Yaml,Json}`): бандл однороден,
  переписывать его в другой формат приложение не вправе.
- `save` пишет в `.<имя>.<pid>.tmp` в той же директории, `sync_all`, затем
  `rename`; сорвавшаяся запись оставляет прежний файл целым, временный убирается.
  Живёт в `core`, потому что карта крейтов отдаёт прогресс `core`, а `offline` —
  это загрузка материалов; запрет для `core` касается Tauri, диалогов и UI, а не
  `std::fs`.

## Статусы

- Записанный статус и действующий — разные вещи. `core::status::effective`
  считает действующий поверх записанного и ничего не пишет: `blocked` выводится
  из графа, `stale_passed` — из `verified_at` и сегодняшнего дня. Оба меняются
  без участия человека, поэтому в файле им места нет.
- Сегодняшний день приходит параметром (`Date`). Часы — окружение, а `core`
  остаётся чистым и проверяемым без подмены времени.
- Порядок разрешения: `passed_out` из `calibration.passed_out` перекрывает файл;
  зачтённое стареет; `blocked` ставится только не-зачтённому. Зачёт сильнее
  блокировки — `blocked` отвечает на вопрос «рано ли начинать», а начали уже
  давно.
- `Date` живёт в `core/src/date.rs` и держит весь календарь: разбор, сравнение,
  прибавление дней. `yaml/dates.rs` спрашивает у него «это дата?» и добавляет
  только время и сдвиг RFC 3339.

- Отметка руками — тоже попытка, `source: manual`. Отдельного поля «поставлено
  человеком» нет: история остаётся одной лентой, сброс не стирает `attempts[]`, а
  «рукой или зачётом» читается из источника последней попытки
  (`TopicState::marked_by`). Схема требует вердикт у каждой попытки, поэтому
  статус кладётся на ближайший законный вердикт, а правда — в `status` плюс
  `source`.

## Сканер бандла

`core/src/scan/` — единственное место, где модель бандла встречается с файловой
системой. Корень задают снаружи: сканер смотрит ровно в переданный каталог и не
угадывает — ни подъёма к ближайшему `roadmap.*`, ни обхода подкаталогов.

- Граница «отказ или деградация»: нечитаем **бандл целиком** (нет `roadmap.*`,
  лежат оба, роадмап не читается или не парсится) → `Err(ScanError)`; нечитаема
  **одна тема** → она уходит в `absent` или `broken`, а остальные читаются.
- Два вида отсутствия разведены намеренно: `absent` несёт флаг `generated` того
  этапа. Тема несгенерированного этапа — штатное состояние (ADR-007), тема
  сгенерированного — потеря, и её отдельно назовёт валидатор.
- Валидатору сканер отдаёт только разобранные темы: `validate(&Roadmap, &[Topic])`
  остаётся вне ФС, а «файл темы потерян» выводится из состава набора.
- `examples/llm-agents-base` держит **оба** формата (и `roadmap.yaml`, и
  `roadmap.json`, и обе версии каждой темы) — это корпус фикстур, а не бандл:
  сканирование его каталога законно кончается `AmbiguousFormat`.

## Слияние при перегенерации

`core/src/merge/` — `merge(&mut Document, &Roadmap, before, after) -> Report`.
Слияние идёт по `id` (ADR-009) и **правит файл прогресса**, возвращая отчёт:
`kept`, `stale` с перечнем изменившихся частей, `added`, `orphaned`.

- Старую версию тем передаёт вызывающий (зеркало прогресса и история версий живут
  в app-data). `core` между запусками ничего не хранит и сравнивает два набора,
  которые ему дали.
- «Содержательное наполнение» — то, чему учат и что проверяют: `depends_on`,
  `outcomes`, `misconceptions`, `practice`, `questions`, `exam`. Переписанный
  заголовок, сдвинутые часы, новая ссылка на материал и свежий `verified_at`
  зачёт не роняют: человек доказал ровно то, что требовали.
- Понижается только `passed` → `stale_passed`. `passed_out` и уже `stale_passed`
  не трогаются, а незачтённые статусы менять не за что.
- Состав программы решает **роадмап**, а не набор файлов: тема, которую генератор
  ещё не написал, осиротевшей не считается (иначе незавершённый бандл по ADR-007
  осиротил бы половину прогресса).

## Сводка прогресса

`core/src/summary/` — `summarize(&Roadmap, &[Topic], &Statuses) -> Summary`.
Сводка по программе и по каждому этапу роадмапа: `done`/`total`, `stale`,
`hours_done`/`hours_total` и `share()`.

- В знаменатель идёт тема, у которой `priority` — `core` или `recommended`
  (правило S02: `optional` учится по желанию и долю не портит) **и** есть
  разобранный документ. Несгенерированная и битая тема из знаменателя выпадают:
  иначе незавершённый бандл по ADR-007 никогда не дойдёт до 100%.
- Пройдено — `status::is_done` (`passed`, `passed_out`, `stale_passed`), то же
  правило, что в S07. Протухший зачёт вдобавок считается отдельным числом
  `stale`: иначе доля падала бы сама, от одной смены даты.
- Часы остаются диапазоном `Hours` — вилка `est_hours` из бандла, без
  придуманной точности. Остаток и среднее считает тот, кто показывает.

## Рендер промпта экзаменатора

`core/src/prompt/` — `render(&str, &Topic, &Roadmap) -> Result<String, RenderError>`.
Текст `examiner.md` передаёт вызывающий: рендер — чистая функция, ФС остаётся
за сканером.

- Промптом является **только** фрагмент между первым и вторым `---`. Шапка
  «копируется в бандл» и хвост «что трекер делает с результатом» адресованы
  человеку и автору бандла, а не модели на зачёте.
- Скаляр подставляется в строку; коллекция раскрывается **вложенным
  markdown-списком** под своим пунктом — вопрос становится блоком с типом,
  сигналами, красными флагами и добивочным, `check` — с командой и ожиданием.
- Пустое значение вырезает свою строку-пункт целиком: заголовок без данных
  модель достраивает сама. Режется строка, а не `##`-секция, иначе вместе с
  пустотой уехал бы `topic_id`, на который ссылается вердикт.
- Неизвестный или незакрытый `{{…}}` — ошибка с именем ключа: неподставленные
  скобки в промпте портят зачёт у человека, и лучше не начать, чем начать так.
- Форма промпта пришпилена golden-файлом `fixtures/golden/examiner/`, сравнение
  идёт байт в байт.

## Парсер вердикта

`core/src/verdict/` — `parse(&str, &Topic) -> Result<Verdict, VerdictError>`.

- Вердикт ищется как **последний** блок свободного текста: сначала ограждённый
  ```json, и только если такого нет — последний балансный `{…}`. Модель почти
  всегда дописывает разбор после блока и правит себя повтором; последний блок и
  есть итог. Сканер балансных скобок помнит строки и экранирование, поэтому
  `{` внутри цитаты блоком не считается.
- Отказ (`Err`) — только там, где применять нечего: нет JSON, JSON не разобран,
  чужой `topic_id` (в ошибке названы оба), нет `topic_id` или `verdict`,
  `per_question` отсутствует или пуст. Пустой разбор вопросов — это вердикт без
  оснований, ему верить нельзя.
- Неполный вердикт разбирается (`Ok`) с перечнем `missing`: чего не хватает,
  решает человек, а не парсер. Ответ на вопрос, которого у темы нет, тоже не
  отказ — он попадает в `unknown_questions` вместе с разобранным ответом.
- `raw` хранит блок как пришёл: `Attempt` (S06) записывает его в бандл дословно.

## Применение протокола

`core/src/protocol/` — `apply(&Verdict, &Topic, Option<&TopicState>, at, today)
-> Applied { state, retry, split_suggested }`. Чистая функция: старое состояние
не мутируется, запись в файл остаётся за `Document` (S06).

- Таблица «вердикт → статус» из [protocol.md](../docs/protocol.md) покрыта
  целиком. `pass` ставит `passed_at` (дата вердикта, а если её нет — день
  применения) и `next_review_at` по `retention`; `partial` возвращает очередь
  вопросов с `result != ok`; `fail` переносит `gaps` вердикта в состояние;
  `blocked` оставляет тему `in_progress`.
- Вердикт, который не `pass`, не трогает прежние `passed_at`/`next_review_at`:
  зачёт был, и история этого не теряет. `pass`, наоборот, чистит `gaps`.
- Попытка `blocked` **пишется** в `attempts[]` — `raw` и факт «артефакт не
  предъявлен» дороже чистоты счётчиков, — но `counted()` её отбрасывает, и в
  серию провалов она не входит.
- Три `fail` подряд считаются по хвосту `attempts[]`: `blocked` прозрачен, любой
  другой вердикт обрывает серию, ручная отметка `failed` считается наравне —
  провал темы остаётся провалом независимо от того, кто его поставил.

## Парсер бандла

`core/src/yaml/` — тонкий слой над `saphyr`: `Reader` ходит по документу с
сохранением пути поля (`topics[0].priority`, `practice.acceptance[0].id`),
`ParseError` несёт код, строку, колонку, путь и сообщение. Своих типов документов
слой не знает, но знает словарь, общий для всех: `text`, `optional_text`
(nullable — `"type": ["string","null"]` в схеме темы), `number(minimum)`, `flag`,
`choice` по таблице вариантов, `list`, `texts`, `entries`. Разбор одного вида
документа — своя папка: `core/src/roadmap/`, `core/src/topic/` (`types` — форма,
`parse` — чтение, у темы ещё `enums` — девять закрытых словарей: у roadmap их два,
и они лежат прямо в `parse`). Публичные входы —
`roadmap::parse(&str)`, `topic::parse(&str)`. Общее между документами живёт в
корне крейта: `tolearn_core::Hours` — `[min, max]` из `est_hours`.

Решения, которые в схеме не видны:

- **Неизвестное поле** пропускается (мягкий парсер), **неизвестное значение
  `enum`** — ошибка: `priority: urgent` нельзя молча посчитать чем-то, от него
  зависит знаменатель прогресса.
- Ошибка несёт **машинный код** — `ParseFailure::code()`: `yaml.syntax`,
  `yaml.missing-field`, `yaml.wrong-type`, `yaml.out-of-range`,
  `yaml.unknown-value`, `yaml.document-count`. UI и тесты ветвятся по коду, проза
  сообщения — для человека. `thiserror` слой не берёт: `Display` собирается из
  позиции, пути и кода, данных в вариантах нет, производить `#[error]` нечего.
- Колонка у `saphyr` считается с нуля, строка — с единицы; `ParseError`
  нормализует обе к единице, потому что число едет человеку в сообщение.
- `version_pins` — `BTreeMap`: порядок автора теряется, зато поиск пина по имени
  (S51) и вывод детерминированы.
- Даты остаются строками, пока никто не считает по ним арифметику; тип даты
  появится там, где появится счёт (S07).
- BOM снимается с начала источника до разбора: иначе он приклеивается к первому
  ключу и файл с видимым `schema:` падает с «поля нет».
- Nullable-поле (`published`, `covers_version`, `delta`, `starting_point`,
  `fallback`, `follow_up`) — это `Option<String>`, но **поле обязано быть**:
  `null` значит «сознательно нет», отсутствие ключа — забыли заполнить, и это
  ошибка. Пустой строкой `null` не подменяется: «даты нет» и «дата пустая» —
  разные факты для S13.
- Поле `type` в YAML читается в `kind` на стороне Rust — `type` там ключевое
  слово. Затронуты `Material`, `Question`; больше `type` в схемах нет. По той же
  причине тир материала — `MaterialTier`, а не `Tier`: голое имя рядом с
  `PracticeTier` не читается и заняло бы слово, нужное следующим документам.

Граница строгости: парсер отвечает за **форму** — тип значения, наличие поля,
арность `est_hours`, `minimum` у чисел, которые едут в вычисления. Кардинальность
(`minItems`), паттерны и согласованность документов — не его слой: их держат
схемный гейт (S02) и валидатор целостности (S05). Отсюда то, что парсер
пропускает молча и что ловится выше: пустые `stages`/`topics`, `est_hours` с
`min > max`, дубли ключей YAML (побеждает последний — `saphyr` схлопывает их в
загрузчике, хука на дубль у него нет).

## Валидатор целостности

`core/src/bundle/` — `validate(&Roadmap, &[Topic]) -> Vec<Violation>`: то, что нельзя
увидеть внутри одного документа. В ФС не ходит **намеренно** — какие темы дошли до
валидатора, решает сканер (S09); «потерянный файл темы» выводится из того, что тема
объявлена в манифесте этапа с `generated: true`, а документа с таким `id` в наборе нет.

Решения, которые из спеки не видны:

- Валидатор **собирает все** нарушения, а не падает на первом: `tolearn validate` (S17)
  показывает человеку весь список за один прогон. Отсюда `Vec<Violation>`, а не `Result`.
- `Violation` — enum со **структурными** данными (`id`, `stage`, цепь цикла), текст
  собирается в `Display`. Код машинный, свой словарь `bundle.*` — отдельный от `yaml.*`:
  это другой слой, и UI ветвится по коду.
- Позиции (строка, колонка) у нарушения **нет**: оно живёт между двумя файлами, а
  разобранные `Roadmap`/`Topic` маркеров не хранят. Тащить их через все типы — правка
  закрытых S03/S04, и цена не оправдана.
- Цикл ищется по **компонентам сильной связности** (Тарьян, `scc.rs`), а не по рёбрам
  назад: иначе одна замкнутая группа тем даёт столько сообщений, сколько в ней обходов.
  Цепь внутри компоненты — кратчайший цикл через её первую по порядку манифеста тему,
  поэтому вывод детерминирован. Самозависимость — цепь из одного звена.
- Мажор схемы — последний сегмент после `/` без `v`. Нечитаемый мажор даёт `0`, а версии
  начинаются с единицы, поэтому мусор в `schema` отвергается как несовпадение, и
  отдельного вида нарушения под него не заводится.
- Чекпойнт разделён на два нарушения: `bundle.unknown-checkpoint` (такой темы нет) и
  `bundle.checkpoint-outside-stage` (тема есть, но лежит в другом этапе). Это разные
  поломки бандла, и чинятся они по-разному.

Не его слой: `est_hours` с `min > max` и дубли ключей YAML — они внутри одного документа
и ждут S05a (см. `progress.md`).

Контракт появляется в S25: команды объявляются в одном месте, типы для UI
генерируются оттуда же, рукописная команда мимо описания ломает тест. До S25
файла `api.md` в `.context/` нет намеренно — описывать нечего.
