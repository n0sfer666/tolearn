# Проверки

Машинно-читаемый компаньон для pre-commit-хука — [checks.json](checks.json).
Здесь то же самое для человека плюс то, что в хук не влезает.

## Обязательные перед коммитом

| Что | Команда |
|---|---|
| типы / компиляция | `cargo check --workspace --all-targets` |
| форматирование + линт | `cargo fmt --all -- --check; cargo clippy --workspace --all-targets -- -D warnings` |
| тесты | `cargo test --workspace` |
| UI: типы и разметка | `pnpm -C ui lint` |
| UI: токены, контраст, конвенция имён | `pnpm -C ui tokens` |
| UI: сборка, маршруты, вес JS | `pnpm -C ui test` |
| Экспорт: CommonMark и markdownlint | `pnpm -C ui markdown` |
| Плагин Obsidian: типы | `pnpm -C obsidian lint` |
| Плагин Obsidian: тесты | `pnpm -C obsidian test` |

Nushell: `and` между командами не работает как в bash — команды разделяются `;`,
проваленная прерывает конвейер сама.

Предупреждение clippy = ошибка. Ослаблять `-D warnings` нельзя; нужен
`#[allow]` — точечно и с причиной.

Внешний форматтер (хук редактора) переписывает порядок импортов в файлах, которых
задача не касалась, причём в порядок, который `cargo fmt --all -- --check`
отвергает. Поэтому перед стейджингом смотреть `git status`: файлы вне задачи —
откатить (`git checkout --`), свои — прогнать через `cargo fmt --all`. Источник
правды по стилю — `cargo fmt`, а не хук.

## Сколько стоит полный прогон

| Что | Время |
|---|---|
| `cargo fmt --all -- --check` | 0.3 с |
| `cargo clippy --workspace --all-targets -- -D warnings` по горячему | 2.8 с |
| `cargo test --workspace` по горячему, 830 тестов | 14 с |
| пересборка всех 92 тест-бинарников после правки в `core` | 10 с |
| весь набор из чистого `target/` (fmt + clippy + test) | 2 м 35 с |
| UI-гейты (`pnpm -C ui lint; pnpm -C ui test`) | 28 с |

Числа держатся, пока `target/` не разросся. Cargo не убирает артефакты старых
отпечатков: за месяц работы каталог дошёл до **77.8 ГБ и 625 200 файлов**, и на
этом `cargo test --workspace` по горячему стоил 26 минут при 53 % CPU — время
уходило не на компиляцию, а на обход каталога, индексацию Spotlight и XProtect.
После `cargo clean` то же дерево собирается вхолодную за минуту и занимает 4.9 ГБ.

Отсюда правило: `du -sh target` больше ~10 ГБ — `cargo clean`. Линковка узким
местом не является, менять линкер незачем: сборка идёт на 820–920 % CPU.
`[profile.dev]` держит `debug = "line-tables-only"`, зависимости — без отладочной
информации вовсе; на сборке это ~12 %, но главное — артефакты не разбухают.
Паники в тестах при этом сохраняют `файл:строка`.

## Мутационная проверка

Тест, зелёный с первого прогона, ничего не доказывает, пока не показано, что он
умеет падать. Проверяется так: ломается проверка в коде, гоняются тесты, смотрится
список упавших.

Гоняет это `scripts/mutate.sh`: без аргументов — вердикт по уже наложенной в
рабочем дереве правке, `-l scripts/mutations.tsv` — по набору
(`имя<TAB>файл<TAB>было<TAB>стало`, замена литеральная, откат через
`git checkout`). Лог построчно в `target/mutate.log`, прогресс `N/M` в stdout.

### Два круга

| Круг | Команда | Зачем |
|---|---|---|
| близкий | `CARGO_TARGET_DIR=target/near cargo nextest run --workspace --exclude tolearn-app --cargo-profile mutants` | убить мутацию дёшево |
| дальний | `CARGO_TARGET_DIR=target/far cargo nextest run --workspace --no-fail-fast --cargo-profile mutants` | право сказать «выжила» |

Вердикт **«убита»** ставится по близкому кругу: чтобы мутация считалась пойманной,
достаточно одного упавшего теста, и он почти всегда лежит в том же крейте.
Вердикт **«выжила»** — только после полного прогона по всему воркспейсу без
`--fail-fast`: иначе не видно ни тестов `app`, ни остальных упавших бинарников,
и счёт падений выходит заниженным.

Три вещи, из которых складывается скорость обоих кругов:

- **свой `CARGO_TARGET_DIR` у каждого круга** (`target/near`, `target/far`).
  Смешивать разные наборы крейтов в одном каталоге нельзя: cargo пересчитывает
  фичи и обесценивает отпечатки, каждый второй прогон становится полной
  пересборкой. Дефолтный `target/` при этом остаётся чистым для обычной работы.
- **профиль `mutants`** (`Cargo.toml`): `inherits = "dev"`, без отладочной
  информации и без инкрементальности — линковка перестаёт быть узким местом.
- **`cargo-nextest`** вместо `cargo test`: процесс на тест, параллельно, и
  fail-fast по умолчанию. Доктестов в воркспейсе нет, поэтому nextest покрывает
  `cargo test --workspace` целиком. Коды выхода различают беду: `100` — упал
  тест (мутация убита), `101` — не собралось (мутация не компилируется, вердикта
  нет), `124` — таймаут раннера.

### Сколько это стоит

| Что | Было | Стало |
|---|---|---|
| пересборка тестов после правки в `core` | 333 с | — |
| один вердикт | 15–20 мин | 26 с (близкий круг) |
| вердикт с эскалацией на дальний круг | — | 539 с |
| близкий круг вхолодную | — | 75 с |
| близкий круг по горячему, 611 тестов | — | 22.75 с |
| дальний круг на профиле `dev` | — | не уложился в 45 мин |
| дальний круг на профиле `mutants`, 795 тестов | — | 7.3 с (сборка 1 м 18 с) |

Отладочная информация в дальнем круге стоила дороже всей сборки. Пока он ходил
в дефолтный `target/`, прогон не укладывался в 45 минут, и время уходило не на
тесты: `sample` показывал тест-бинарники висящими в `_dyld_start`, то есть до
`main`. Первый запуск свежеслинкованного бинарника macOS проверяет целиком, а
тест-бинарники `app` тянут Tauri и весят с отладочной информацией сотни
мегабайт; тот же бинарник вторым запуском отдаёт список тестов за секунду.
Отсюда же `SLOW [>180s]` у тестов `cli` и `offline`, которые поднимают дочерний
процесс: платится не тест, а первый `exec`. Поэтому лёгкий профиль у обоих
кругов — набор тестов от него не меняется, меняется только вес бинарника.

Таймауты: шаг близкого круга `MUTATE_NEAR_LIMIT` (900 с), дальнего
`MUTATE_FAR_LIMIT` (2700 с), весь прогон `MUTATE_LIMIT` (10800 с). Вышедший за
таймаут шаг помечается `таймаут-<круг>` и не считается ни убитой, ни выжившей —
лучше честный `таймаут-дальний`, чем ложное «выжила».

Перед набором обязательно прогоняется базовый близкий круг: на красном дереве
любая мутация выглядит убитой, и вердикты были бы ложными.

Мутация, не уронившая ни одного теста, — находка, а не повод расслабиться: либо
дыра в тестах, либо мёртвый код. В S05 так нашёлся мёртвый ранний выход в поиске
цикла.

## По уровням проверки

| Уровень | Что запускается |
|---|---|
| T1 | `cargo check` + `cargo clippy` + рассуждение по edge-кейсам |
| T2 | то же + `cargo test --workspace`, для CLI — вызов бинарника на фикстурах |
| T3 | сборка и запуск приложения, скриншот, проверка клавиатуры |
| T4 | регрессионный тест, пиннящий дефект |

## Вес JS

Бюджеты из [architecture.md](../docs/architecture.md#бюджеты) держит
`ui/scripts/budget.mjs`: он считает gzip всего JS страницы — встроенного,
подключённого и подтянутого транзитивно (чанки острова видны только по
атрибутам `<astro-island>`, в `<script src>` их нет). Отдельно посмотреть —
`pnpm -C ui budget`, гейтом это гоняется внутри `pnpm -C ui test`.

## Экспорт в Markdown

`ui/scripts/markdown.mjs` копирует эталонный бандл во временный каталог без
`.json`-двойников (иначе экспорт видит два `roadmap.*` и отказывается), гоняет
`tolearn export` и проверяет результат `markdownlint-cli2` по
`.markdownlint-cli2.jsonc` в корне. Отключены три правила: длина строки
(`MD013`), одинаковые заголовки у разных тем (`MD024`, только среди соседей) и
инлайновый HTML (`MD033`) — остальное чинится в генераторе, а не послаблением
правила. Посмотреть — `pnpm -C ui markdown`, в CI это отдельный шаг job `ui`.

## Тесты UI

`pnpm -C ui test` гоняет `node --test` с `--test-concurrency=1`. Последовательно —
не для красоты: тест-файлы поднимают `astro build` в общий `dist/`, и два
параллельных прогона роняют сборку друг другу.

## Плагин Obsidian

`obsidian/` — отдельный пакет, из воркспейса `ui/` не виден и своей вёрстки не
имеет. `pnpm -C obsidian lint` — это `tsc --noEmit`; `pnpm -C obsidian test` —
`node --test tests/*.test.mjs`, где тесты импортируют `.ts`-исходники напрямую:
Node снимает типы сам, отдельного шага сборки для тестов не нужно.
`pnpm -C obsidian build` собирает `main.js` через esbuild — артефакт, в git не
кладётся. Единственный модуль с вводом-выводом — `src/host.ts`; вся остальная
логика чистая, потому и проверяется без Obsidian.

## Токены

`ui/scripts/tokens.mjs` читает `docs/design/tokens.css` напрямую (копии в `ui/`
нет, алиас `@design`) и держит три вещи разом: конвенцию именования из
[visual-system.md](../docs/design/visual-system.md#токены) (шкала носит префикс
семейства, семейство из одного члена отвергается, два одиночных токена с общим
первым сегментом обязаны стать семейством), запрет хардкода в стилях приложения
(hex, `px`, брейкпойнт кроме объявленных, `outline: none` без замены) и контраст
WCAG — 4.5:1 для текста, 3:1 для `--color-border-strong` и `--color-focus`, на
обеих темах и всех трёх поверхностях. `light-dark()` разбирается по веткам:
просадка только в тёмной находится отдельным тестом. Посмотреть —
`pnpm -C ui tokens`, гейтом гоняется и там, и внутри `pnpm -C ui test`.

## Распознавание речи

В `checks.json` этого нет намеренно: прогон требует сабмодуля whisper.cpp,
сборки его через cmake и весов модели вне репозитория — на каждом коммите такое
не гоняют.

```
git submodule update --init --recursive
cargo clippy -p tolearn-speech --features speech --all-targets -- -D warnings
TOLEARN_WHISPER_MODEL=~/.cache/tolearn/models/ggml-small-q5_1.bin cargo test -p tolearn-speech --features speech -- --nocapture
```

Без `--features speech` крейт собирается пустым, и его тесты (`wav`, `wer`,
`attribution`, `memory`) идут в общем `cargo test --workspace`. С фичей
добавляются `listen` и `corpus`; без весов оба пропускаются, печатая, чего не
хватает, — «зелено» без модели ничего не доказывает, смотреть надо на
`--nocapture`. Числа бюджетов печатает сам `corpus`.

Nushell: переменная окружения ставится через `with-env`, а не префиксом —
`with-env {TOLEARN_WHISPER_MODEL: ...} { cargo test ... }`.

Добавлять команду в `checks.json` **только** когда она реально существует и

## CI

`.github/workflows/ci.yml`, на push в `master`/`dev` и на pull request (push в
прочие ветки не гоняется намеренно: PR из них и так проверяется, двойной прогон
не нужен):

- job `format` — `cargo fmt --all -- --check`, одна ОС;
- job `check` — `cargo clippy --workspace --all-targets --locked -- -D warnings`
  и `cargo test --workspace --locked` на матрице ubuntu / macos / windows;
- job `speech` — сабмодуль, скачивание весов со сверкой sha256 и прогон
  `tolearn-speech` под фичей `speech` на ubuntu / macos. Windows подключается в
  S58 вместе с упаковкой варианта `-with-speech`.

`--locked` обязателен: `Cargo.lock` в репозитории, и молча разъехавшийся lock —
это уже не та сборка, которую проверяли. Гейт веса JS живёт в `ui/` (job `ui`: `pnpm -C ui lint` и `pnpm -C ui test`,
последний сам собирает `dist/`; там же шаг `pnpm -C ui markdown`); гейт веса установщика добавляется в S57.
