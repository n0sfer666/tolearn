# Коммиты и ветки

## Стиль

Сложившийся в репозитории стиль (см. `git log`) — **не** conventional commits:

```
Add project foundation: architecture decisions, spec breakdown, design system
Split ADRs into docs/adr, add speech and remote-access decisions, extend specs to S60
Drop remote device access: remove ADR-011 and specs S55-S56
```

Правила:

- английский, повелительное наклонение, с заглавной буквы, без точки в конце;
- одна строка до ~72 символов; при необходимости — двоеточие и перечисление
  того, что вошло;
- тело — только когда нужно объяснить «почему»; «что» видно из диффа;
- ссылка на спеку в теле, когда коммит закрывает спеку: `Closes S01.`;
- никаких `Co-Authored-By`, `Generated by` и прочих меток.

## Ветки

`master` — основная. Работа идёт в `dev`. Прямо в `master`/`main` не коммитим.

Имя ветки под задачу — `sNN-<краткое-описание>` (`s01-workspace-skeleton`),
чтобы ветка читалась вместе со спекой. Ветка создаётся только по согласованию.

## Гранулярность

Один коммит = одна смысловая единица. Спека обычно закрывается одним коммитом;
если её DoD распадается на независимо проверяемые части — серией, но вся серия
делается сразу, не копится.

Изменения `.context/` едут в коммите задачи, которая их вызвала, либо отдельным
`Update project context: …`.

## Перед коммитом

Проверки зелёные (`.context/checks.md`), `git diff --staged` просмотрен на
секреты, файлы стейджатся поимённо. Сломанное или непроверенное не коммитится.
