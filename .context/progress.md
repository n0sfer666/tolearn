| S07 Статусы и производные | done | `core/src/status/` (`effective` — действующий статус, `review` — `next_review_at`, `verdict` — таблица «вердикт → статус») и общий `core/src/date.rs` (`Date`: разбор, сравнение, `plus_days`; календарь переехал сюда из `yaml/dates.rs`, который теперь только спрашивает «это дата?»). `effective(&Roadmap, &[Topic], &Progress, today) -> Statuses` **считает рядом**, а не переписывает `progress.yaml`: `blocked` и `stale_passed` зависят от графа и от сегодняшнего дня, хранить их значит хранить протухающее. Сегодняшний день приходит параметром — часы остаются за пределами `core`. Порядок разрешения: `passed_out` из `calibration.passed_out` перекрывает файл → зачтённое стареет по `verified_at + revalidate_after_days` → `blocked` ставится только тому, что ещё не зачтено (зачёт сильнее блокировки), причём `stale_passed` зависимость всё равно считается закрытой. | S08 Ручное управление статусом | done | `Document::mark(topic, &Mark)` (`core/src/progress/mark.rs` — `Mark` и сборка попытки, `document.rs` — правка дерева) и `core::status::manual` — сборка отметки из статуса и сегодняшнего дня. Отметка руками пишется **попыткой с `source: manual`**, а не отдельным полем: история остаётся одной лентой, `attempts[]` при сбросе не трогается, а статистика отличает руку от зачёта по `TopicState::marked_by()` — источнику последней попытки. Схема требует вердикт у каждой попытки, поэтому статус кладётся на ближайший законный вердикт (`todo`/`in_progress`/`exam_pending` → `partial`); правда живёт в `status` + `source: manual`. Ручной зачёт датирует себя ровно как экзаменационный: `passed_at` = сегодня, `next_review_at` по `retention` темы; не-зачёт обе даты стирает. Ключи правятся на месте, поэтому порядок сохраняется. 14 тестов (`core/tests/progress_manual.rs`) и гейт `cli/tests/gate/written.rs` — каждый из восьми статусов, записанный приложением, всё ещё проходит `progress.schema.json`. Доказан семью мутациями |

| S09 Сканер бандла | done | `core/src/scan/` (`mod` — обход, `types` — `Scan`/`Absent`/`Broken`, `error` — `ScanError`). `scan(&Path) -> Result<Scan, ScanError>`: корень — **сам каталог**, подъёма по дереву и рекурсии вниз нет, «где корень» решает вызывающий (CLI/UI). Формат бандла — тот, в котором лежит роадмап; лежат оба, нет ни одного, роадмап не читается или не парсится → `Err`, потому что бандл целиком нечитаем. Всё остальное деградирует: тема без файла попадает в `absent` (с флагом `generated` того этапа — «ещё не сгенерирована» по ADR-007 против настоящей потери), тема с битым файлом — в `broken` вместе с жалобой парсера, остальные читаются. Темы возвращаются в порядке роадмапа; файл, которого роадмап не называет, не подхватывается из каталога. 16 тестов (`core/tests/scan.rs`, бандлы собираются во временном каталоге), доказан семью мутациями |

| S10 Слияние при перегенерации | done | `core/src/merge/` (`mod` — обход по роадмапу, `essence` — сравнение содержательного наполнения, `report` — `Report`/`Stale`/`Part`) и два новых примитива записи: `Document::start` (завести тему как `todo`, идемпотентно) и `Document::restate` (сменить статус без попытки). `merge(&mut Document, &Roadmap, before, after) -> Report` правит файл и возвращает отчёт по каждому случаю: `kept`, `stale` (с перечнем изменившихся частей), `added`, `orphaned`. Старую версию тем даёт вызывающий (зеркало app-data по ADR-009) — `core` ничего не хранит между запусками. Содержательное наполнение — `depends_on`, `outcomes`, `misconceptions`, `practice`, `questions`, `exam`; заголовок, часы, материалы и `verified_at` зачёт не роняют. Понижается только `passed` → `stale_passed`. Исчезнувшая тема остаётся в файле нетронутой и числится осиротевшей; тема, которую генератор ещё не написал, осиротевшей не считается — состав решает роадмап, а не набор файлов. 12 тестов (`core/tests/merge.rs`) и гейт `cli/tests/gate/merged.rs` (файл после перегенерации проходит `progress.schema.json`). Доказан семью мутациями; шестая нашла непокрытую идемпотентность `start` — закрыта тестом |
