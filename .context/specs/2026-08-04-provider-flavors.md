# Спецификация: выбор вида LLM-провайдера (локальная модель / HTTP API / CLI-харнесс)

Дата: 2026-08-04. Источник: интервью с владельцем проекта.
Спеки: **S62** (виды и харнесс), **S63** (рекомендации и параметры),
**S64** (журнал запросов), **S65** (генерация программ, заявка).

## Контекст

S41 и S42 закрыты: крейт `provider/` умеет два вида (`Flavor::Ollama`,
`Flavor::OpenAi`), хранит `enabled`/`flavor`/`endpoint`/`model` в
`<app-data>/provider.yaml` (`schema: tolearn/provider/v1`), ключ — в системном
хранилище через `keyring`, `check` возвращает список моделей, `ask` шлёт один
запрос и отдаёт сырой ответ. Экран — остров `ui/src/islands/Provider.tsx` на
`/settings/`, второй потребитель — `/exam/` (кнопка «Спросить модель»).

Чего нет: выбора «локально или через внешний CLI», рекомендаций по моделям и
железу, управления параметрами генерации, запуска процессов из `provider/`.

Смежное: `runner/` (S16) умеет таймаут, лимит вывода и убийство дерева
процессов, но запускает `sh -c`, держит stdin закрытым и написан под unix.

## Требования

### Функциональные

**Три вида в одном radio** (`active`), у каждого своя панель полей и свои две
кнопки проверки:

1. `local` — локальная модель: `api` (`ollama` либо `openai` — llama.cpp,
   LM Studio, vLLM), `endpoint`, `model`, `num_ctx`, `temperature`,
   рекомендации моделей по железу. API выбирается руками: сервер не обязан
   говорить, кто он, а молчаливое угадывание маршрута прячет причину отказа.
   Ключ у локального вида не спрашивается ни при каком `api`.
2. `remote` — OpenAI-совместимый HTTP: `endpoint`, `model`, ключ в keychain.
3. `harness` — внешний CLI-харнесс: выбор из реестра либо своя команда,
   `command`, `args`, `timeout`.

**Реестр харнессов** — вшитый, четыре пункта: Claude Code, opencode, pi и «Своя
команда». Запись реестра даёт **пресет** `command`/`args`; оба поля показаны и
правятся руками — чужой CLI сменит флаги, и человек починит настройку сам, не
дожидаясь обновления приложения.

**Две ступени проверки, одинаковые у всех трёх видов:**

| | «Проверить» (дёшево) | «Пробный запрос» (по-настоящему) |
|---|---|---|
| `local` (`api: ollama`) | `GET /api/tags` → список моделей; выбранной нет → отказ с `ollama pull <model>` | микро-промпт через `/api/chat`, ответ показан |
| `local` (`api: openai`) | `GET /models` без ключа | микро-промпт через `/chat/completions` |
| `remote` | `GET /models` с `Bearer` | микро-промпт через `/chat/completions` |
| `harness` | бинарник найден и ответил на `--version` | микро-промпт через stdin, ответ показан |

Микро-промпт — короткая просьба ответить одним словом. Для `harness` это
единственный способ отличить «бинарник есть» от «залогинен и работает».

**Микро-промпт ограничен по длине и принимает рассуждение.** У reasoning-модели
одно слово стоит тысяч токенов размышления: без потолка пробный запрос упирается
в 180-секундную границу, а ответ приходит пустым, потому что слова лежат не в
`content`. Поэтому проба просит не больше 128 токенов (`max_tokens` у
OpenAI-совместимого, `options.num_predict` у Ollama) и, если `content` пуст,
берёт `reasoning_content` / `thinking`: проба доказывает, что сервер отвечает, а
не качество ответа. Экзамену это послабление не передаётся — там пустой `content`
остаётся отказом, и длина ответа не режется.

**Запуск харнесса изолирован:** cwd — пустой временный каталог (не бандл, не
app-data), промпт уходит в stdin, аргументы пресета отключают инструменты и
правки файлов, по завершении каталог удаляется.

**Переключение вида ничего не теряет:** конфиг держит настройки всех трёх видов
одновременно плюс поле «какой активен».

### Нефункциональные

- Тесты без сети, без внешних аккаунтов, без установленных CLI.
- Запуск харнесса работает на macOS, Windows и Linux.
- Провайдер выключен по умолчанию; выключенный не ходит ни в сеть, ни в процесс.
- Ключи и секреты не попадают в конфиг (`provider.yaml` — открытый текст).
- Бюджет JS `/settings/` из `docs/architecture.md` не превышается.

## Архитектура

### Конфиг: `tolearn/provider/v2`

```yaml
schema: tolearn/provider/v2
enabled: false
active: local          # local | remote | harness
local:
  endpoint: http://127.0.0.1:11434
  api: ollama          # ollama | openai (llama.cpp, LM Studio, vLLM)
  model: ""
  num_ctx: 16384
  temperature: 0.2
remote:
  endpoint: ""
  api: openai
  model: ""            # ключ — только в keychain
harness:
  id: claude           # claude | opencode | pi | custom
  command: claude
  args: ["-p", "--output-format", "text"]
  timeout_secs: 180
log_requests: false
```

**Миграция v1 → v2** обязательна: старый файл читается, плоские поля
перекладываются в `local` (при `flavor: ollama`) или `remote` (при
`flavor: openai`), `active` берётся из старого `flavor`, ключ в keychain
остаётся на месте. Тест на фикстуре v1 пиннит перенос.

### Слои и крейты

- `runner/` получает второй вход: `spawn(program, args, dir, stdin, limits)` —
  запуск **программы с аргументами** (без шелла), с подачей stdin, таймаутом,
  лимитом вывода и убийством дерева процессов. Кроссплатформенно: различается
  только убийство (`kill -TERM -<pgid>` против `taskkill /T /F`) — одна
  `#[cfg]`-развилка. Существующий `run` не трогается.
- `provider/` начинает зависеть от `runner/` (гейт слоёв обновляется). Общее
  между HTTP и процессом — форма ответа и коды отказов, они уже в `error.rs`.
- `provider/src/harness.rs` — реестр пресетов, сборка команды, разбор вывода.
- `provider/src/recommend.rs` (S63) — таблица моделей и сверка с RAM.
- `sysinfo` (MIT, совместим с GPL-3.0) — новая зависимость ради объёма RAM,
  вносится в `.context/stack.md`.

### Разбор вывода харнесса

Ответ — **весь stdout**, из него вырезаны ANSI-последовательности. Баннеры
разбору вердикта не мешают: S13 берёт последний JSON-блок из свободного текста.
`stderr` идёт только в текст ошибки.

- Код возврата ≠ 0 → отказ `harness.failed(код)` с первыми строками stderr.
- Пустой stdout при коде 0 → `provider.bad-answer`.
- Вывод превысил потолок (1 МиБ, настраиваемый под S65) → отказ
  `harness.truncated`, а не половина JSON в разбор вердикта.
- Таймаут → `harness.timeout`, дерево процессов убито.
- Бинарник не найден → `harness.not-found` с подсказкой про `which`.

## API / Интерфейсы

IPC остаётся одной командой `provider(...)`, расширяется полями:

```text
provider {
  save: ProviderView | null,     # весь конфиг v2, включая неактивные секции
  key: string | null,
  forget: bool,
  check: bool,                   # первая ступень
  probe: bool,                   # вторая ступень: микро-промпт
}
→ { provider, has_key, checked: {models[]} | null, probed: {said, took_ms} | null }
```

`examine(bundle, topic)` не меняет форму: маршрутизация по `active` живёт внутри
`provider::ask`, промпт по-прежнему рендерит `core::prompt::render`, разбор и
запись остаются `parse_verdict`/`apply_verdict`.

Коды отказов (переводятся в `ui/src/lib/provider.ts`, один текст на оба экрана):
`provider.disabled`, `provider.no-key`, `provider.no-model`,
`provider.not-installed(model)`, `provider.unreachable`, `provider.rejected`,
`provider.answered(код)`, `provider.bad-answer`, `harness.not-found`,
`harness.failed(код)`, `harness.timeout`, `harness.truncated`.

## UI/UX

**`/settings/`, остров Provider:**

- Radio из трёх видов. Под каждым — строка о том, куда уходят данные: у `local`
  «данные не покидают машину», у `remote` и `harness` — «текст задания и ваш
  ответ уйдут во внешний сервис под вашим аккаунтом».
- Панель полей активного вида; поля неактивных видов не показаны, но сохранены.
- `local`: список рекомендованных моделей с весом, отметкой «установлена» и
  готовой командой `ollama pull` для остальных; тяжёлые для этой машины помечены
  (S63). Поля `num_ctx` и `temperature` с рекомендуемыми значениями рядом.
- `harness`: выпадающий список реестра, поля `command`/`args`/`timeout`. Под
  `args` — предупреждение: ключи сюда не вписывать, поле хранится открытым
  текстом; харнесс берёт авторизацию из своего логина.
- Кнопки «Проверить» и «Пробный запрос» у каждого вида. На время запроса кнопка
  неактивна, рядом — «Идёт запрос… 12 с из 180».
- Галочка «Вести журнал запросов» (S64), выключена по умолчанию, рядом —
  «Открыть папку» и «Очистить».

**`/exam/`:** кнопка называет активный вид — «Спросить qwen3:8b», «Спросить
Claude Code». Остальное поведение прежнее: ответ ложится в то же поле, что и
вставленный руками, отказ объясняется словами и не стирает введённое.

Доступность и локализация — по общим правилам S28/S40: radio управляется с
клавиатуры, у каждого пункта видимый фокус; все тексты — в словарях, имена
моделей и команд не переводятся.

## Edge Cases

| Случай | Поведение |
|---|---|
| GUI-приложение на macOS не видит `~/.local/bin` | `harness.not-found` + подсказка «выполните `which claude` и вставьте полный путь» |
| Харнесс не залогинен | первая ступень зелёная, вторая — отказ с текстом stderr |
| Харнесс висит | таймаут, дерево убито, каталог удалён |
| Харнесс печатает гигабайт | обрезка → `harness.truncated`, память не съедена |
| Выбранная модель не установлена в Ollama | проверка провалена, показан `ollama pull` и список установленных |
| Провайдер выключен | ни сети, ни процесса — отказ до всякой работы |
| Файл v1 на диске | прочитан и перенесён в v2, ключ не потерян |
| Переключение вида туда-обратно | ни одно поле не потеряно |
| В `args` вписан ключ | предупреждение показано; в тексты ошибок аргументы не попадают |

## Риски и митигации

| Риск | Вероятность | Митигация |
|---|---|---|
| Агент-харнесс пишет файлы или запускает команды | высокая | пустой временный cwd, пресеты с флагами без инструментов, промпт в stdin |
| Зомби-процессы после таймаута | средняя | убийство **дерева** в `runner`, одна реализация на проект |
| Пресеты реестра устаревают вслед за чужими CLI | высокая | `command`/`args` правятся руками; «Своя команда» покрывает всё остальное |
| Секрет в `args` утекает в лог или тост | средняя | предупреждение в UI; аргументы не попадают в тексты ошибок |
| Промпт с ответами человека оседает на диске | средняя | журнал выключен по умолчанию, ротация, кнопка «Очистить» (S64) |
| Обрезанный ответ принят за вердикт | средняя | обрезка — отказ, а не частичный результат |
| Таблица рекомендованных моделей стареет | высокая | у таблицы дата и оговорка, что это ориентир; список установленных всегда живой |
| Windows-ветка запуска не проверена | средняя | тесты на подставном бинарнике идут на всех трёх ОС в CI |

## Тестовая стратегия

**Уровень: T2 + T3.**

T2 — крейты и IPC:

- Подставной бинарник `fake-harness` (`[[bin]]` в крейте, путь из
  `CARGO_BIN_EXE_*`): умеет ответить заготовкой, повиснуть, упасть с кодом,
  сыпать ANSI, печатать больше потолка, эхом вернуть прочитанный stdin.
  Работает на трёх ОС, шелл не нужен.
- Заглушка HTTP на `127.0.0.1` из `app/tests/support` — как в S41/S42.
- Пиннится: изоляция cwd (харнесс видит пустой каталог), промпт дошёл до stdin,
  таймаут убивает дерево, обрезка даёт отказ, код ≠ 0 даёт отказ, ANSI срезан,
  миграция v1 → v2, переключение вида не теряет полей, выключенный провайдер не
  запускает процесс.

T3 — экран: запуск приложения, переключение radio, обе кнопки на каждом виде,
скриншот; проверка, что выбор переживает перезапуск (шов S61).

Мутации — по образцу S41/S42: снятая проверка «выключен», подмена команды мимо
пресета, потеря `stdin`, игнор кода возврата, игнор потолка вывода, пропуск
миграции v1.

## Разбиение на спеки

| № | Результат | Зависит |
|---|---|---|
| S62 | Три вида в radio, конфиг v2 с миграцией, запуск CLI-харнесса с изоляцией и таймаутом, реестр пресетов, две ступени проверки у всех видов, кнопка зачёта называет вид | S41, S42, S16, S38 |
| S63 | Рекомендации моделей по RAM, отметка установленных, `ollama pull` для недостающих, поля `num_ctx` и `temperature` | S62 |
| S64 | Журнал запросов: галочка (выключен по умолчанию), последние N записей с промптом и ответом, «Открыть папку» и «Очистить» | S62, S38 |
| S65 | Генерация программ через провайдера («абсолютный промпт» S43 гоняется активным видом, ответ разбирается в бандл) | S43, S62 |

S62 закладывает запас под S65: потолок вывода и таймаут настраиваются и
вмещают сотни килобайт — это проверяется тестом на большом ответе, а сам экран
генерации в S62 не делается.

## Открытые вопросы

- Точные аргументы пресетов opencode и pi проверяются вживую при реализации;
  в CI они не проверяемы по определению (чужих CLI там нет).
- Значение N для журнала (S64) назначается при реализации, ориентир — 20 записей.
- Отмена долгого запроса кнопкой не делается: потребовала бы IPC с ручкой
  задачи, которого в проекте пока нет вовсе. Появится потребность — отдельная
  спека.
