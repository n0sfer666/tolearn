# Спецификация: генерация программ моделью и диалоговый зачёт

Дата: 2026-08-06. Источник: интервью с владельцем проекта.
Спеки: **S65** (генерация программы), **S66** (диалоговый зачёт и видимые
входы), **S67** (зачёт по программе), **S56** (голосовой ответ, уже в плане).

## Контекст

Провайдер настроен и работает: три вида (`local`, `remote`, `harness`), выбор
API у локального, совет по моделям, `num_ctx` и `temperature` (S62, S63).
`provider::ask` шлёт один запрос и отдаёт сырой ответ, `examine(bundle, topic)`
собирает промпт экзаменатора тем же `core::prompt::render`, что и копипаст-цикл.
Промпт генерации лежит текстом в `core/assets/generate.md`, вкомпилирован в ядро
и прибит гейтом `cli/tests/gate/prompt.rs`: в тексте обязано найтись каждое поле
схем (91 путь), каждое значение `enum` и каждый код `bundle.*`.

Чего нет: программу нельзя создать из приложения — только импортировать готовую
папку. Зачёт идёт одним заходом: большой промпт → сырой вердикт → применение;
вопросы не задаются по одному, проверить можно только тему целиком, а вход в
проверку спрятан внутри `/exam/`.

## Решения интервью

| Вопрос | Решение |
|---|---|
| Что спрашиваем до генерации | свободное поле «чему хочу научиться» + уровень, часы в неделю, срок |
| Ожидание | модалка с прогрессом и отменой, без стриминга |
| Дробление | два шага: скелет `roadmap.yaml`, затем тема за запрос |
| Промпт | два файла, гейт полноты делится вместе с ними |
| Брак | сами просим модель починить, до 3 кругов, прогресс виден |
| Приёмка | сводка (этапы, темы, часы) и кнопка «Принять» до записи |
| Место | `<app-data>/bundles/<id>`, автоматически |
| Объём | оценка времени после скелета, отмена; жёсткого потолка нет |
| Язык | как язык интерфейса |
| Перегенерация существующей | вне этой работы |
| Вопросы диалога | вопросы темы + добивающие уточнения модели |
| Конец диалога | модель предлагает, человек подтверждает |
| Обрыв | диалог сохраняется и продолжается после перезапуска |
| Срок жизни диалога | до вердикта либо до явного «Начать заново» |
| Подсказки | разрешены и честно помечают `hinted` |
| Входы в проверку | главное действие на экране темы + ход из очереди повторений |
| Стоимость | время и токены запроса видны на экране |
| Порядок | S65 → S66 → S67 → S56 |

## S65 — генерация программы активным провайдером

### Требования

Кнопка «+» на `/programs/` — заметное главное действие рядом с импортом. Провайдер
выключен → кнопка неактивна и говорит, чем включается, а не исчезает.

Форма: одно свободное поле «чему хочу научиться» плюс уровень (новичок /
знаю основы / уверенно), часы в неделю и желаемый срок. Язык бандла — язык
интерфейса, поля в форме под него нет.

Два шага генерации, оба тем же путём, что и промпт экзаменатора (`provider::ask`,
любой из трёх видов провайдера):

1. **Скелет** — `generate-roadmap.md`: `roadmap.yaml` со списком тем, этапами,
   `depends_on` и оценками часов. Разбирается и валидируется сразу; темы ещё не
   сгенерированы, поэтому этап помечен `generated: false` — это уже умеет S09.
2. **Темы** — `generate-topic.md`, по запросу на тему, с контекстом: заголовок и
   `id` темы, её место в графе, оценка часов, язык.

После скелета экран показывает: сколько тем, сколько заняла первая, оценку
общего времени, и продолжает только по подтверждению. Отмена — в любой момент;
отменённая генерация не оставляет ни файла на диске.

**Брак.** Ответ не прошёл разбор или валидацию → отдаём модели список нарушений
`bundle.*` тем же путём и просим исправить, до трёх кругов на один артефакт.
Круги видны («тема 3 из 12, попытка 2 из 3»). Три круга не помогли → генерация
останавливается, нарушения показаны словами, полубандла на диске нет.

**Приёмка.** Собранный бандл проходит полную валидацию **в памяти**, затем экран
показывает сводку: этапы, число тем, суммарные часы, первые темы каждого этапа.
Запись на диск — только по «Принять». Место — `<app-data>/bundles/<id>`,
без вопросов; после записи программа регистрируется в реестре (S15) как
импортированная, и экран уходит на неё.

**Стоимость.** У каждого шага видно время; токены — когда провайдер их сообщил
(`eval_count` у Ollama, `usage` у OpenAI-совместимого; харнесс не сообщает
ничего, и это сказано, а не заполнено нулями).

### Границы

`core` знает про промпты и разбор, `provider` — про запрос, `app` — про сборку
шагов и запись. Знание про Tauri и UI в `core` не течёт (правило проекта).
Перегенерация существующей программы — не здесь: слияние S10 готово, спека будет
отдельной. В чужой бандл по-прежнему не пишется ничего (ADR-009): генерация
создаёт **новый** каталог, а не правит существующий.

### Гейт промпта

`generate.md` делится на `generate-roadmap.md` и `generate-topic.md`; общая часть
(правила формата) дублируется в обоих — это текст для модели, а не код, и каждый
файл обязан читаться самостоятельно. Гейт делится вместе с ними: от первого
требуются все пути `roadmap.*` и коды `bundle.*`, относящиеся к скелету, от
второго — все `topic.*`. Ни одно поле схемы не должно потеряться при делении:
объединение двух требований покрывает прежний 91 путь, и это проверяется тестом.

### Перед экраном — ручной прогон

До того как строить UI, оба промпта прогоняются вручную на живой модели. CLI сюда
не годится: гейт слоёв запрещает `cli` зависеть от `provider`, поэтому прогон идёт
через мост `app/examples/bridge.rs` — теми же IPC-командами, что будет звать экран.
Результат проходит `tolearn validate`. Прогон недетерминирован и в CI не живёт, но
он отвечает на вопрос «промпт вообще работает» до того, как в него упрётся экран.

### DoD

Кнопка «+» на `/programs/` создаёт валидную программу из одной фразы человека:
скелет и темы приходят разными запросами, брак чинится до трёх кругов, отказ не
оставляет полубандла, сводка показывается до записи, принятая программа
открывается сразу. Проверка: **T2 + T3** (живой прогон на локальной модели).

## S66 — диалоговый зачёт

### Требования

Вход — главное действие на экране темы («Проверить себя»), не ссылка в списке
секций; второй ход — прямо из очереди повторений (S44). Копипаст-цикл остаётся
как есть: провайдер выключен → работает он, и это по-прежнему наблюдаемо.

Диалог ведёт модель: берёт вопросы темы из бандла **по одному** и может
добивать уточнениями. Отсебятины вместо вопросов темы нет — вердикт обязан
лечь на `per_question`, иначе разбор (S36) и статистика (S52) теряют опору.

**Подсказка** — кнопка рядом с полем ответа. Подсказка разрешена и помечает
вопрос `hinted: true`: обучение важнее чистоты цифры, но цифра честная.

**Конец.** Вопросы кончились → модель предлагает завершить, решает человек.
Кнопка «Завершить» жива всегда — оборвать можно на любом вопросе. По завершении
модель выдаёт тот же JSON-вердикт и тот же протокол применяет его; ничего нового
в `progress.yaml` не появляется.

**Обрыв.** Незаконченный диалог живёт в app-data: один на тему, переживает
перезапуск, при возврате продолжается с того же места. Исчезает по вердикту либо
по явному «Начать заново». Попытка (`attempts[]`) появляется **только** по
вердикту — как и сегодня.

**Стоимость.** Время и токены каждой реплики видны, как и в S65.

### Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| История диалога перерастает `num_ctx` мелкой модели | высокая | вопросы идут по одному, в контекст уходит тема + текущий вопрос + ответы по нему, а не вся переписка целиком |
| Модель «забывает» выдать вердикт в формате | средняя | завершение шлёт отдельный промпт вердикта — тот же, что в копипаст-цикле |
| Сохранённый диалог ссылается на изменившуюся тему | низкая | при расхождении содержания темы диалог помечается устаревшим и предлагается начать заново |

### DoD

Зачёт по теме проходится разговором: вопросы по одному, подсказка помечает
`hinted`, завершение даёт вердикт того же формата, прерванный диалог
продолжается после перезапуска приложения. Проверка: **T3**.

## S67 — зачёт по программе

Сквозной прогон поперёк тем одной программы: приложение выбирает темы (готовые
к повторению и пройденные), диалог идёт смешанно, вердикт выносится по каждой
затронутой теме отдельно — общего «вердикта по программе» в протоколе нет и
заводить его не будем. Детали — отдельным интервью перед стартом спеки.
