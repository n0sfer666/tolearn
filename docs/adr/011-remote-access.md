# ADR-011. Доступ с другого устройства — HTTP-зеркало контракта

Читать материалы с планшета, пока ноутбук занят, — понятное желание, и фронтенд
у нас статический, так что раздать его кажется бесплатным. Это не так, и цену
надо назвать вслух.

`ui` общается с ядром **только** через Tauri IPC. В обычном браузере
`window.__TAURI__` не существует, поэтому раздать те же страницы недостаточно:
нужен HTTP-API, повторяющий весь контракт IPC. Это второй транспорт к тому же
ядру — в том числе и тот локальный порт, за который ADR-002 отверг вариант B.

Решение — сделать это честно и узко:

- контракт объявляется **один раз**, IPC и HTTP генерируются из него, расхождение
  ломает тест (S55). Два рукописных списка команд разъедутся в первый же месяц;
- режим **только для чтения**: изменяющие команды по HTTP не экспонируются
  вообще. Не «защищены», а отсутствуют;
- выключено по умолчанию, включается явно, с показом интерфейса, на котором
  слушает;
- сопряжение по коду из приложения; токен — заголовком, не в URL: URL оседает в
  истории, логах и `Referer`;
- HTTPS с самоподписанным сертификатом, отпечаток показан для сверки. LAN — не
  доверенная среда, а без TLS по ней открытым текстом идут и токен, и содержимое.

Если по итогам S55 окажется, что генерация контракта в два транспорта тянет за
собой больше, чем стоит функция, — правильный ход отказаться от режима, а не
поддерживать два расходящихся API.
