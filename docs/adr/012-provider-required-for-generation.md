# ADR-012. Провайдер нужен генерации, а не чтению

Ограничения 1–2 в [architecture.md](../architecture.md#ограничения-из-которых-всё-следует)
написаны для v1, где бандл целиком приходит снаружи и приложение только его
читает. В v2 приложение само генерирует каждый этап (ADR-013), и генерация без
LLM не работает — молчать об этом было бы враньём.

Разделение по действию:

| Действие | Нужен провайдер? |
|---|---|
| Открыть бандл, читать материал, вести прогресс, проходить практику уже сгенерированного | нет — ни сети, ни ключа, ни модели |
| Сгенерировать этап | да |
| «Уточнить» | да |
| Проверить письменный ответ зачёта | да |
| Скопировать промпт зачёта в чужой чат и вставить вердикт руками | нет — копипаст остаётся путём, не требующим от приложения ничего |

Провайдером считается и локальная модель (S63, подбор по железу) — требование
«без аккаунтов и ключей» не снимается им же: снимается только «без LLM вообще»
для операций, которые без LLM бессмысленны. Ключ и аккаунт не становятся
обязательными нигде, включая генерацию. Тесты сети по-прежнему не видят:
фикстуры вместо запросов, как и было.

Ограничения переписаны:

1. Приложение не имеет права требовать сеть для уже сгенерированного: чтение,
   прогресс и практика работают офлайн. Генерация этапа, «Уточнить» и проверка
   письменного ответа вправе требовать провайдера — сеть нужна, только если
   выбранный провайдер удалённый.
2. Приложение не имеет права требовать аккаунт, ключ или оплату — ни для
   чтения, ни для генерации: локальная модель считается провайдером наравне с
   платным, ключ и аккаунт не становятся обязательными.
