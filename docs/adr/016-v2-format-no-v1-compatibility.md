# ADR-016. Формат v2 без совместимости с v1

Формат v1 (`learning-roadmap/v1`, `learning-roadmap/topic/v1`,
`learning-roadmap/progress/v1`) уходит целиком вместе с тестами и эталоном
`examples/llm-agents-base`, а не получает конвертер или режим совместимости.
Программа v1 не открывается — приложение говорит это прямо отдельным
сообщением, а не падает на разборе схемы или сваливается в общую ошибку
импорта.

## Почему без совместимости

Формат v1 описывал бандл, который целиком собирает внешний генератор
(скилл `learning-roadmap`); v2 описывает программу, которую собирает
поэтапно само приложение ([ADR-013](013-incremental-program-generation.md)).
Это не эволюция одной схемы, а другая модель данных, и конвертера v1 → v2 не
будет.

Цена, названная прямо: программы v1, которые у владельца уже есть, в v2 не
откроются, и прогресс по ним не перенесётся. Продолжить такую программу в v2
можно одним способом — сгенерировать её заново. Скилл `learning-roadmap`,
который выпускал v1, удалён ([S86](../specs/README.md)).

## Имена схем

Схемы v2 получают собственное имя вместо `learning-roadmap/*`: семейство
называлось так потому, что его выпускал скилл `learning-roadmap`, а этого
внешнего генератора больше нет.

## Эталон

Правило «эталон менять нельзя» (`.context/README.md`) действует для
`examples/llm-agents-base` только до тех пор, пока эталон v2 не заведён в
группе B; после этого оно переходит на новый v2-эталон. Само удаление кода
v1 и `examples/llm-agents-base` — отдельные спеки группы B, не эта.

## Альтернативы и пересмотр

Отвергнуто: **конвертер v1 → v2** (другая модель данных; у программы v1 нет
контекста генерации, без которого следующий этап не сгенерировать); **чтение
v1 рядом с v2** (два формата в ядре навсегда, тесты и эталон держат старую
модель); **имя `learning-roadmap/*`** (скилла больше нет).

Пересмотреть, если у v1 найдутся пользователи кроме владельца: тогда
отдельной спекой — перенос карты тем без прогресса.
