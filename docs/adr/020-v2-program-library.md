# ADR-020. Программа v2: библиотека, каталог, блоки

Программа v2 живёт в библиотеке приложения, в app-data, и делится на
каталоги с разными писателями:

| Данные | Писатель | Где |
|---|---|---|
| содержимое: карта, этапы, ассеты | генерация и импорт | `<data>/programs/<uuid>/` |
| пользовательское: прогресс, уточнения, ответы зачёта | приложение по действию человека | `<data>/state/<uuid>/` |
| текст проверенных источников | генерация | кэш в app-data, не часть программы |

В каталог содержимого пишут только генерация и импорт. Это правило заменяет
правило v1 «в файлы бандла пишется только `progress.yaml`» (`CLAUDE.md`,
[ADR-009](009-user-data-outside-bundle.md)): замена содержимого —
перегенерация этапа, обновление при импорте — не задевает пользовательское
по построению, а не благодаря аккуратности кода. Бандл v1 до своего удаления
(S108) живёт по старому правилу.

## Идентичность

UUID выдаётся при создании программы и не меняется никогда. Slug — читаемое
имя для глаз и для имён файлов при экспорте, уникальным ему быть не нужно.
Совпадение UUID на импорте — та же программа
([ADR-021](021-tolearn-package.md));
одинаковые названия у разных людей не сливаются.

## Каталог

```
programs/<uuid>/
  program.yaml        цель, уровень, карта, источники, контекст генерации
  stages/*.yaml       этап: блоки, практика, вопросы зачёта
  assets/             SVG и картинки
  children/<uuid>/    подпрограмма — такой же каталог
```

`program.yaml` держит цель, уровень, карту (подпрограммы, этапы и часы по
строке), метаданные источников (url, ISBN, глава, лицензия, `checked_at`) и
контекст генерации. Среда пользователя (ОС, железо — S63) в программе не
хранится: генерация берёт её с машины в момент вызова. Готовые этапы остаются
под среду того, кто их сгенерировал, следующий — под среду того, кто
генерирует.

Этап — YAML со списком блоков `{id, kind, text}`, практикой и вопросами
зачёта с эталонными ответами. Формат на диске не зависит от формата ответа
модели: модель может отвечать JSON, приложение пишет YAML и читает его тем же
разбором с местом ошибки, что у v1.

Подпрограмма лежит в `children/<uuid>/` каталога родителя и имеет свой UUID;
глубина — не больше трёх уровней, этапы только у листьев, родитель —
контейнер ([ADR-013](013-incremental-program-generation.md)). Одно дерево —
один каталог: ссылок между программами нет, и осиротеть им нечему.

## Блоки

Виды блоков: `paragraph`, `heading`, `code`, `callout`, `diagram` — Mermaid,
отрисованный при генерации в SVG-ассет, с исходником для деградации
([ADR-014](014-model-text-app-verified-sources.md)), и `image` — ассет с
лицензией и атрибуцией. Текст блока — подмножество разметки S69: то, чем
приложение уже рисует текст модели.

`id` блока — короткий префикс sha256 его текста; блоки этапа с одинаковым
текстом получают суффикс по порядку появления. Длину префикса назначает S97.
Следствие, названное прямо: неизменённый абзац переживает перегенерацию
вместе со своими уточнениями ([ADR-015](015-clarifications-outside-bundle.md)),
изменённый — даже правкой опечатки — их сиротит. Осиротевшие не удаляются
(ADR-009).

## Практика

Модель v1 по смыслу не меняется: задача, результат, две коллекции —
`constraints` и `acceptance` — с `claim` и `expect` прозой. `check`
необязательна: команда есть только там, где есть что запускать. Вердикт
выносит человек, команда запускается только по нажатию
([ADR-006](006-human-verdict.md)). Текст задачи — блоками с `id`, чтобы его
можно было уточнять.

## Схемы

Семейство `tolearn/*`: `tolearn/program/1` и `tolearn/stage/1`; пакет —
`tolearn/package/1` (ADR-021); состояние — `tolearn/state/1`, его заводит
группа D вместе с первым писателем. JSON Schema draft 2020-12 без внешних
`$ref`, как у v1: схема проверяется без сети.

## Данные v1

Файлы v1 в app-data (реестр, распакованные бандлы, история, индекс поиска,
офлайн-хранилище) v2 не читает и не удаляет: код не делает с файлами
пользователя ничего необратимого. Что из v1 уходит — ADR-022.

## Альтернативы и пересмотр

Отвергнуто:

- **папка на выбор пользователя**, как в v1: папку перемещают, удаляют,
  открывают двумя копиями, и в одном каталоге два писателя. Вынос библиотеки в
  свою папку — отдельной спекой, если понадобится;
- **Markdown этапов с `id` в атрибутах**: `{#b1}` теряется при правке руками и
  моделью, уточнения сиротеют;
- **SQLite на программу**: бинарный файл — чужой текст модели не виден без
  приложения, диффа нет;
- **slug как идентичность**: две «chiptune» разных людей неразличимы и
  сливаются;
- **подпрограммы отдельными программами со ссылками**: битые ссылки, когда
  ребёнка удалили, и экспорт, который собирает граф;
- **порядковый `id` блока** — после перегенерации уточнение молча прилипает к
  другому абзацу; **случайный** — любая перегенерация сиротит все уточнения
  этапа;
- **`progress.yaml` внутри программы**: замена содержимого обязана аккуратно
  переносить его;
- **текст источников в программе**: чужие страницы уезжают с пакетом — вопрос
  авторского права и веса.

Пересмотреть хэш-`id`, если после перегенерации осиротевшими оказывается
большинство уточнений на абзацах, не изменившихся по смыслу, — то же условие,
что в ADR-015. Пересмотреть библиотеку в app-data, если понадобится
синхронизация программ через облачную папку.
