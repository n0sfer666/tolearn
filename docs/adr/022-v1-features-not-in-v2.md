# ADR-022. Что из v1 не переживает v2

Группа B переводит приложение на программу v2
([ADR-020](020-v2-program-library.md)), и функции, построенные на темах v1,
либо пересобираются на v2, либо уходят. Здесь записано, что куда, чтобы
удаление кода не выглядело самодеятельностью отдельной спеки.

## Уходят в группе B без замены

- очередь повторений (S44);
- план и прогноз (S45);
- граф зависимостей (S46);
- история версий (S49);
- таймер практики (S50);
- дайджест устаревания (S51);
- статистика (S52);
- очередь и переключатель офлайна (S24), свежесть (S60);
- выгрузка программы (S68);
- генерация «+» (S43, S65) — её заменяет поэтапная генерация группы C
  ([ADR-013](013-incremental-program-generation.md)).

Вернуть любую — своей спекой с решением, а не восстановлением кода v1: все
они считают по темам и статусам v1, которых в v2 нет.

## Уходят в группе B, хотя зачёт живёт

Диалоговый зачёт (S66) и зачёт по программе (S67) уходят в группе B, а не в
D, как было записано в [ADR-017](017-written-exam-only.md): их вход — темы
v1, и после B их нечем кормить. Вместе с ними уходит вход голосового ответа
(S56). Крейт `speech` и его ручки остаются до группы D, где решается,
возвращается ли голос в письменный зачёт.

## Переживают и пересобираются на v2

- поиск (S39) — пересобирается в группе B на текст этапов;
- практика с раннером, копипаст-зачёт, вердикт, статусы и сводка прогресса
  ([ADR-013](013-incremental-program-generation.md), ADR-017) —
  пересобираются в группе D на состояние `<data>/state/<uuid>/`.

Их экраны v1 уходят в группе B. Цена, названная прямо: между B и D программу
v2 в сборке dev можно только читать — ни практики, ни зачёта, ни статусов.

## Крейт `offline`

Остаётся. Хранилище (S18), загрузка (S19) и читалка (S20) нужны группе C
для проверки источников ([ADR-014](014-model-text-app-verified-sources.md));
пререндер и видео (S21–S23) ждут решения группы C. Это то отдельное решение,
без которого ADR-014 запрещал удалять код офлайна. Решение группы C —
[ADR-023](023-generation-pipeline.md): пререндер остаётся, зеркало, `repo` и
видео уходят.

## Порядок

Эталон v2 → экраны читают v2 → уход ядра v1. Приложение ни на одном коммите
не остаётся без программы, которую можно открыть: эталон приходит пакетом
`.tolearn` ([ADR-021](021-tolearn-package.md)) раньше, чем уходит импорт v1.

## Данные v1

Реестр, распакованные архивы, история версий, индекс поиска и офлайн-хранилище
v1 в app-data программа v2 не читает и не удаляет: код не делает с файлами
пользователя ничего необратимого. Где они лежат и что их можно удалить
руками — в руководстве пользователя; в «Помощи» приложения — группа F.

## Альтернативы и пересмотр

Отвергнуто:

- **удалить `offline` целиком**: группа C потеряет загрузку и читалку, на
  которых стоит проверка источников;
- **перенести офлайн на источники v2 сейчас**: решение о пререндере и видео
  принадлежит группе C, в B для него нет вопроса;
- **удалить v1 до эталона v2**: между коммитами приложению нечего открыть;
- **отложить уход экранов и ядра v1 до реализации дизайна**: два формата в
  ядре на весь срок групп C–E, и каждый экран пишется дважды;
- **удалить данные v1 при первом запуске**: необратимо и без спроса;
- **перенести данные v1 в `legacy-v1/`**: та же запись в файлы пользователя
  без его действия, а читать их там всё равно нечем.

Пересмотреть, если между B и D пройдёт больше одной группы: тогда практику и
статусы на v2 — отдельной спекой раньше D, чтобы сборка не жила долго в режиме
«только читать».
