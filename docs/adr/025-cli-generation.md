# ADR-025. Генерация из CLI

[ADR-023](023-generation-pipeline.md) разложил генерацию на шаги,
[ADR-024](024-request-ledger.md) — учёт их времени и токенов. Здесь — как те же
шаги запускаются из терминала без окна: куда пишется программа, откуда берётся
провайдер, что печатается и чем CLI отличается от приложения. Решения интервью
S126 от 2026-09-13.

## Команды

```
tolearn new "<запрос>" --level <уровень> --out <каталог> [--provider <файл>] [--json]
tolearn next <каталог> [--choice <номер>] [--provider <файл>] [--json]
```

`new` строит карту (`plan::plan`) и первый этап (`start::start`), `next` без
`--choice` показывает варианты развилки (`fork::known`, иначе
`fork::propose`), с `--choice N` строит выбранный (`fork::take`). Порядок
вызовов и отказы — те же функции `generate`, что у приложения; CLI добавляет
только сбор зависимостей и вывод.

## Свой каталог данных, а не библиотека

`<каталог>` — корень данных в том же формате, что у приложения:
`<каталог>/programs/<uuid>/` — программа, `<каталог>/cache/` — кэш источников,
развилки и журнал запросов. В библиотеку приложения CLI не пишет: результат
забирается `tolearn pack` и импортом S102, как любой другой пакет.

`new` отказывает, если в каталоге уже лежит программа, и называет
`tolearn next`. `next` работает с каталогом, где программа ровно одна, и ведёт
её от последнего созданного этапа: сначала подпрограммы — с последней строки
`children` карты, затем последняя строка карты, у которой этап уже есть.

Каталог внутри хранилища приложения (`~/.local/share/tolearn` или его XDG-замена)
обе команды отвергают до любой работы: путь сравнивается после разрешения
ссылок и `..`, так что обходной путь к тому же каталогу тоже отказ.

После записи итог собирается из дерева той программы, чей uuid вернула
генерация. Если прочитать его не удалось, команда говорит, что программа
записана, и называет путь: повторять генерацию не нужно.

Отвергнуто: писать в библиотеку приложения. CLI тогда делит каталог с
запущенным приложением без общего замка, а тест не может проверить результат,
не подменяя XDG.

## Провайдер

Файл провайдера — тот же `provider.yaml` из каталога настроек приложения (XDG,
`~/.config/tolearn`), язык программы — из `settings.yaml`. Ключ читается из
той же записи системного хранилища (`Keychain::app()`) и только для
удалённого провайдера: локальная модель и харнесс хранилища не касаются, так
что им отказ хранилища не мешает. Хранилище не ответило — отказ «ключ
провайдера не прочитан» до сети. `--provider <файл>` подменяет только файл.
Выключенный провайдер в настройках — отказ с подсказкой включить его в
приложении или назвать файл, в названном файле — отказ с путём и
`enabled: false`; названного файла нет — отказ с путём.

`next` без `--choice`, когда развилка уже в кэше, показывает её, не читая
провайдера: `--provider` в этом случае не проверяется.

Проверка сети — та же `online` до первого вызова модели: без сети команда
отказывает с `generate.offline` и модель не зовёт.

## Вывод

Строки шагов — в stderr, по одной на завершённый шаг, в порядке завершения:

```
карта · 4.2 с · 3 104 → 1 870 ток.
источники · 1.3 с · 1 204 → 380 ток.
текст · 9.8 с · 5 410 → 2 960 ток.
схемы · 0.0 с · схемы остались исходником Mermaid: окна для схем нет
запись · 0.1 с
```

Токены шага — сумма вызовов модели внутри него (обёртка над моделью считает
каждый ответ, и отказ модели тоже — как вызов без данных); провайдер не
сообщил число — «без данных о токенах: N». Шаг без вызовов модели, как
«запись», токенов не показывает.
Разряды разделяет неразрывный пробел.

Итог — в stdout, чтобы его можно было забрать в скрипт:

```
программа: <каталог>/programs/<uuid>
этап: <id> · <время> · <вход> → <выход> ток.
дальше: tolearn next <каталог>
```

`--json` печатает итог объектом: `program`, `path`, `node`, `stage`, `title`,
`ms`, `calls`, `input`, `output`, `unknown`, `mermaid`; у вариантов развилки —
`program`, `node`, `after`, `variants[] {choice, id, title, hours, why,
recommended}`. Номер варианта в CLI — с единицы.

## Схемы без окна

Отрисовка Mermaid в SVG живёт в скрытом окне приложения (S121). У CLI окна нет:
художник всегда отказывает, и схема деградирует до исходника — блок кода
`mermaid`, как у приложения при сбое отрисовки. Строка шага «схемы» говорит об
этом, `mermaid` в JSON — число таких отказов.

## Чего у CLI нет

- Журнала промптов `app/src/journal`: журнал запросов ADR-024 в
  `cache/<uuid>/ledger.jsonl` пишется, как у приложения.
- Отмены по Ctrl+C: `Stop` не связан с сигналом, прерванный процесс оставляет
  прежнее дерево — запись атомарна.
- Защиты от двух запусков на одном каталоге.

## Проверка

Тесты `cli/tests/{new,new_refused,next,next_refused,provider}.rs` зовут библиотеку
`tolearn_cli::run` с подставным `World`: HTTP-заглушка Ollama вместо модели,
фикстурные страницы вместо сети, память или всегда отказывающее хранилище
вместо системного.
Подставной харнесс для этого не годится — он не умеет отвечать заданной
последовательностью. Живой прогон — [generate/01-cli.md](../manual-test-cases/generate/01-cli.md).
