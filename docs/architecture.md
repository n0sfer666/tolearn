# Архитектура

Документ фиксирует принятые решения и их причины. Каждое решение — с
альтернативами, которые были отвергнуты, и с условием, при котором его следует
пересмотреть.

## Ограничения, из которых всё следует

1. Приложение не имеет права требовать сеть для основной работы.
2. Приложение не имеет права требовать аккаунт, ключ или оплату.
3. Бандл обучения генерируется снаружи и может быть перегенерирован в любой
   момент. Всё, что создал пользователь, обязано это пережить.
4. Файлы бандла написаны LLM. Они могут быть неполными, невалидными и содержать
   произвольные shell-команды.
5. Размер и скорость — функциональные требования, а не пожелания.

## ADR-001. Оболочка: Tauri 2

Rust-ядро + системный WebView.

Отвергнуто: **Electron** (100+ МБ Chromium в каждой сборке, противоречит
ограничению 5), **нативный UI на egui/iced** (пришлось бы руками рисовать
типографику для длинных учебных текстов — это то, в чём HTML силён, а
immediate-mode GUI слаб), **Flutter** (свой рендерер, +20 МБ, Rust-ядро пришлось
бы дёргать через FFI).

Мобильные приложения делаются позже на этом же ядре: Tauri 2 умеет iOS/Android.
Ядро (`core`) не должен знать ни про Tauri, ни про UI — это условие переиспользования.

## ADR-002. Рендеринг: статическая Astro MPA + острова SolidJS

Требование пользователя — «никаких SPA под капотом, SSR на Astro».

Astro SSR в Tauri напрямую невозможен: SSR требует JS-рантайма на каждый запрос,
а Tauri отдаёт файлы своим протоколом без HTTP-сервера. Рассмотрены три пути:

| | Что это | Цена |
|---|---|---|
| **A (выбрано)** | `astro build` в статические HTML, острова Solid, данные через Tauri IPC | 0 МБ, ~0 мс |
| B | Node-sidecar рядом с приложением, настоящий Astro SSR | +40–90 МБ, порождённый процесс, локальный порт |
| C | Rust отдаёт HTML через `register_uri_scheme_protocol`, шаблоны на minijinja | настоящий SSR без Node, но свой шаблонизатор и потеря Astro-тулинга |

Выбран **A**. Он даёт ровно то, ради чего просили SSR — реальные HTML-страницы,
переходы браузерной навигацией, отсутствие клиентского роутера и гидрации всего
дерева — и при этом не тащит рантайм. В локальном приложении IPC отвечает за
доли миллисекунды, так что «данные уже в HTML» не даёт выигрыша, ради которого
стоило бы платить пунктами B или C.

Пересмотреть, если замеры first paint покажут заметную задержку на экране темы:
тогда вариант C, он остаётся совместимым по разметке.

Правила, которые из этого следуют и не подлежат нарушению:
- никакого клиентского роутера — переходы это `<a href>`;
- остров создаётся только там, где есть состояние (чекбоксы практики, поиск,
  спойлеры). Текст, списки, таблицы — статический HTML;
- никаких веб-шрифтов: системный стек. Шрифт по сети — это и вес, и запрос.

## ADR-003. Офлайн: monolith как библиотека + собственный WebView как рендерер

Подробности — [offline.md](offline.md). Кратко:

- Статьи, доки, спеки → [monolith](https://github.com/Y2Z/monolith) (Rust, CC0,
  используется как библиотека) инлайнит CSS, картинки и шрифты в один HTML.
- Ограничение monolith — у него нет JS-движка, страницы с клиентским рендерингом
  сохраняются пустыми. Решение: у Tauri **уже есть** WebView. Открываем скрытое
  окно, ждём загрузку, забираем `document.documentElement.outerHTML`, и уже этот
  результат отдаём monolith. Ноль новых зависимостей.

Важное следствие для слоёв. WebView живёт в `app`, а не в `offline` — иначе
`offline` начинает зависеть от Tauri, направление зависимостей разворачивается, и
`tolearn scan` перестаёт работать в CI без GUI. Поэтому `offline` объявляет трейт
`Prerenderer` (`url → отрендеренный HTML`), у которого две реализации: заглушка
«отдать исходный HTML как есть» в CLI и настоящая на WebView в `app`. Пререндер
таким образом остаётся необязательным улучшением, а не условием работы загрузчика.
- Читалка — `dom_smoothie` (порт readability).
- `type: repo` → `gix`, `clone --depth 1`.
- Целые сайты документации → сначала пробуем `llms.txt` и `.md`-варианты страниц,
  это самый чистый офлайн-формат; краулер — запасной путь.
- `liveness: paywall | login_required` в материалах — готовый фильтр «не тянуть».

## ADR-004. Видео не качаем сами

`yt-dlp` — это ~35 МБ (внутри PyInstaller-Python), и он **не** включает ffmpeg
(ещё ~70 МБ), без которого нельзя склеить раздельные видео- и аудиодорожки. Итого
>100 МБ ради необязательной функции — прямое нарушение ограничения 5. Плюс
распространение такого бинарника в публичном репозитории — это чужой ToS и
исторический риск DMCA.

Решение: ищем `yt-dlp` и `ffmpeg` в `PATH`. Нет — кнопка скачивания видео
неактивна с объяснением и командой установки. Есть — вызываем как внешний
процесс.

## ADR-005. Кэш офлайн-контента живёт вне бандла

Бандл перегенерируется. Кэш — нет. Хранилище адресуется содержимым:

```
<app-data>/cache/objects/<sha256[0:2]>/<sha256>
<app-data>/cache/index.sqlite   url → sha256, type, fetched_at, size, etag
```

Один и тот же URL в трёх программах хранится один раз. Ревалидация по
`ETag`/`Last-Modified`. Бюджет диска с вытеснением по LRU, порог настраивается.

## ADR-006. Вердикт практики выносит человек, не программа

У практики **две** независимые коллекции проверок, и путать их нельзя:

| | Смысл | Куда идёт |
|---|---|---|
| `practice.constraints[]` | ограничения на форму решения: «клиент содержит ровно один base_url и ни одного литерального ключа» | плейсхолдер `{{practice.constraints}}` |
| `practice.acceptance[]` | приёмка результата: «клиент ходит через шлюз и получает ответ, валидный по своей же схеме» | плейсхолдер `{{practice.acceptance}}` |

Обе имеют одинаковую форму `{id, claim, check, expect}` и обе отображаются на
экране практики. Разделены они не случайно: ограничение можно нарушить, получив
работающий результат, и это разные разговоры на зачёте.

Поле `expect` в обеих написано прозой:

> `constraints[].expect: Первое число не меньше 10, второе не меньше 3.`
> `acceptance[].expect: Печатается SCHEMA_OK, исключения нет.`

Автоматически такое не проверить — и попытка была бы враньём. Поэтому раннер
показывает вывод команды рядом с ожиданием, а отметку ставит человек.

Отдельно: `check` — это произвольный shell, сочинённый языковой моделью. В
эталоне встречается `cd` с записью файлов и `npx promptfoo@latest eval`,
скачивающий пакет из сети. Он **никогда** не выполняется автоматически: только
по явному нажатию, с показом полного текста команды до запуска. Флаг
`smoke_checked: false` — прямое заявление генератора «эту команду никто не
запускал» — показывается рядом с кнопкой.

## ADR-007. Незавершённый бандл — нормальное состояние

В примере `llm-agents-base` заявлено 23 темы, файлов — 7: этапы 2 и 3 помечены
`generated: false`. Это штатный режим генератора, а не битый импорт. Тема без
файла отображается как «ещё не сгенерирована» и не считается ни в знаменателе
прогресса, ни ошибкой.

## ADR-008. Лицензия GPL-3.0

Требование «полностью opensource и fullfree» читается как гарантия для
пользователя, а не только как открытый исходник. GPL-3.0 её удерживает у
производных. Совместимо с зависимостями: monolith — CC0, Tauri — MIT/Apache-2.0,
Astro и Solid — MIT.

## ADR-009. Пользовательские данные живут вне бандла

Ограничение 3 — бандл перегенерируется — не выполняется само собой. В эталоне
`progress.yaml` лежит **внутри** папки бандла, а `examiner.md` прямо
предусматривает режим `refresh` с новыми `id` тем и пометкой `deprecated` у
старых. Значит, перегенерация — не гипотеза, а штатный сценарий, и он обязан
быть спроектирован.

Разделение владения:

| Данные | Владелец | Где |
|---|---|---|
| `roadmap.yaml`, `topics/*.yaml`, `examiner.md` | генератор | папка бандла |
| `progress.yaml` | приложение | папка бандла, но с зеркалом в app-data |
| конспекты | человек | вне бандла ([notes.md](notes.md)) |
| офлайн-кэш | приложение | app-data (ADR-005) |

`progress.yaml` остаётся на месте — он часть формата, и его ценно видеть рядом с
программой, — но приложение держит его копию в app-data и восстанавливает оттуда,
если после перегенерации файл пропал или обнулился.

Перегенерация обрабатывается как **слияние по `id`**, а не как новый импорт:

- тема с тем же `id` — прогресс и конспект сохраняются; если изменилось
  содержательное наполнение, `passed` понижается до `stale_passed`, а не остаётся
  тихо зачтённым;
- тема исчезла — прогресс и конспект **сохраняются** как осиротевшие, а не
  удаляются;
- тема появилась — `todo`;
- `id` изменился — приложение показывает вероятные соответствия и даёт
  перепривязать вручную. Автоматически не угадывает: ошибка привязки здесь
  дороже ручного шага.

Импорт обязан заканчиваться отчётом о слиянии, а не молчаливым «готово».

## Бюджеты

Ограничение 5 бессмысленно без чисел — DoD, который нельзя провалить, не DoD.
Пороги фиксируются в тестах и ломают сборку при превышении:

| Что | Порог |
|---|---|
| Установщик, macOS arm64 | ≤ 12 МБ |
| Установщик, Windows x64 | ≤ 14 МБ |
| JS на странице темы (сжатый) | ≤ 30 КБ |
| JS на странице списка программ (сжатый) | ≤ 15 КБ |
| Открытие темы среднего размера, от нажатия до готового текста | ≤ 150 мс |
| Импорт эталонного бандла (7 тем) | ≤ 300 мс |
| Холодный старт до списка программ | ≤ 800 мс |

Числа взяты как заведомо достижимые для выбранного стека и подлежат ужесточению
по факту замеров, а не ослаблению.

## Структура

```
core/       Rust: типы, парсинг, валидация, прогресс, статусы, протокол
runner/     Rust: исполнение check-команд       (зависит от core)
offline/    Rust: загрузка, архивация, кэш      (зависит от core)
cli/        Rust: tolearn validate|scan|exam    (зависит от core, runner, offline)
app/        Tauri 2: IPC, окна, пререндер       (зависит от core, runner, offline)
ui/         Astro + Solid                       (общается только через IPC)
docs/       решения, спецификации, контракты
examples/   эталонные бандлы, они же фикстуры
```

Направление зависимостей — только вниз. `core` не знает про Tauri, файловый
диалог и UI; `offline` не знает про Tauri (ADR-003). CLI существует не для
пользователей, а чтобы каждый слой можно было прогнать в тестах и в CI без GUI.

## Представление бандла

Генератор кладёт рядом с каждым `.yaml` его `.json`-двойник — это артефакт его
собственного гейта валидации (доказательство, что файл парсится), а не второй
источник правды. Приложение читает **только YAML** и `.json` игнорирует: иначе
пришлось бы решать, что делать при расхождении, которого не должно существовать.

Схем в бандле три, и версии у них независимые: `learning-roadmap/v1` (roadmap),
`learning-roadmap/topic/v1` (темы), `learning-roadmap/progress/v1` (прогресс).
Несовпадение мажорных версий между файлами одного бандла — ошибка импорта, а не
повод угадывать.
