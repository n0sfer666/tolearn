# Архитектура

Ограничения, из которых всё следует, карта решений и числа, которыми они
проверяются. Каждое решение живёт отдельным файлом в [`adr/`](adr/): одно
решение — один документ, с альтернативами, которые были отвергнуты, и с
условием, при котором его следует пересмотреть.

## Ограничения, из которых всё следует

1. Приложение не имеет права требовать сеть для основной работы.
2. Приложение не имеет права требовать аккаунт, ключ или оплату.
3. Бандл обучения генерируется снаружи и может быть перегенерирован в любой
   момент. Всё, что создал пользователь, обязано это пережить.
4. Файлы бандла написаны LLM. Они могут быть неполными, невалидными и содержать
   произвольные shell-команды.
5. Размер и скорость — функциональные требования, а не пожелания.

## Бюджеты

Ограничение 5 бессмысленно без чисел — DoD, который нельзя провалить, не DoD.
Пороги фиксируются в тестах и ломают сборку при превышении:

| Что | Порог |
|---|---|
| Установщик, macOS arm64 | ≤ 12 МБ |
| Установщик, Windows x64 | ≤ 14 МБ |
| Установщик, Linux x64 | ≤ 14 МБ |
| JS на странице темы (сжатый) | ≤ 30 КБ |
| JS на странице списка программ (сжатый) | ≤ 15 КБ |
| JS на странице графа зависимостей (сжатый) | ≤ 60 КБ |
| JS на любой другой странице (сжатый) | ≤ 20 КБ |
| Открытие темы среднего размера, от нажатия до готового текста | ≤ 150 мс |
| Импорт эталонного бандла (7 тем) | ≤ 300 мс |
| Холодный старт до списка программ | ≤ 800 мс |

Потолок установщика — общий: расширения его не расширяют. Всё, что добавляют
zip/tar (S48), age (S53), HTTP-сервер (S55) и TLS с генерацией сертификата
(S56), укладывается в те же 12–14 МБ, и если не укладывается — режется функция,
а не порог.

`-with-speech` — единственное исключение: своей строки в таблице у него нет и
до замера модели в S57 быть не может (ADR-010). Гейт бюджета в CI применяется к
базовому варианту; на `-with-speech` он включается тем же тестом в момент, когда
S57 назначает число.

Числа взяты как заведомо достижимые для выбранного стека и подлежат ужесточению
по факту замеров, а не ослаблению.

## Структура

```
core/       Rust: типы, парсинг, валидация, прогресс, статусы, протокол
runner/     Rust: исполнение check-команд       (зависит от core)
offline/    Rust: загрузка, архивация, кэш      (зависит от core)
cli/        Rust: tolearn validate|scan|exam    (зависит от core, runner, offline)
app/        Tauri 2: IPC, окна, пререндер       (зависит от core, runner, offline)
ui/         Astro + Solid                       (общается только через IPC)
docs/       решения, спецификации, контракты
examples/   эталонные бандлы, они же фикстуры
```

Направление зависимостей — только вниз. `core` не знает про Tauri, файловый
диалог и UI; `offline` не знает про Tauri (ADR-003). CLI существует не для
пользователей, а чтобы каждый слой можно было прогнать в тестах и в CI без GUI.

Это дерево базового варианта, и S01 заводит именно его. Расширения приносят свои
единицы и объявляют их в своих спеках: распознавание речи (S57), HTTP-зеркало
(S55), плагин Obsidian отдельным пакетом (S54). Направление зависимостей на них
распространяется без исключений.

## Представление бандла

Генератор кладёт рядом с каждым `.yaml` его `.json`-двойник — это артефакт его
собственного гейта валидации (доказательство, что файл парсится), а не второй
источник правды. Приложение читает **только YAML** и `.json` игнорирует: иначе
пришлось бы решать, что делать при расхождении, которого не должно существовать.

Схем в бандле три, и версии у них независимые: `learning-roadmap/v1` (roadmap),
`learning-roadmap/topic/v1` (темы), `learning-roadmap/progress/v1` (прогресс).
Несовпадение мажорных версий между файлами одного бандла — ошибка импорта, а не
повод угадывать.
