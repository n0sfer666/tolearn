# Навигация и структура

## Четыре уровня

```
Программы  →  Программа  →  Тема  →  Зачёт / Разбор
```

Глубже не идём. Каждый уровень — отдельная HTML-страница, переход — обычная
ссылка (ADR-002).

## Стартовый экран — всегда список программ

Даже с одной программой. Список — это место, где видно, где ты находишься по
всем направлениям сразу; открывать сразу последнюю программу означает потерять
этот обзор.

Карточка программы: название, предмет, полоса прогресса, количество пройденного
из сгенерированного, дата последней активности. Несгенерированные темы в
знаменатель не входят (ADR-007) — иначе прогресс выглядит вечно провальным.

Импорт — на этом же экране: зона перетаскивания и кнопка выбора папки дают
одинаковый результат.

## Экран программы

Лента этапов сверху вниз. Этап — заголовок, полоса прогресса, список тем.
Чекпойнт визуально отделён от обычных тем: он про весь этап, а не про одну тему.

Тема в списке: глиф статуса, название, оценка часов, метка устаревания если
есть. Заблокированная тема видна, но не кликабельна, и рядом сказано, чем именно
разблокируется.

## Экран темы

Порядок секций повторяет порядок работы, а не порядок полей в YAML:

```
Заголовок          статус, часы, зависимости, свежесть
Результаты         зачем это, наблюдаемо
Заблуждения        читается до материалов, а не после
Материалы          с меткой офлайн-доступности, с признаками stale и delta
Практика           задача, ограничения, приёмка — отдельный экран, если велика
Вопросы            только формулировки
Зачёт              действие
Конспект           всегда доступен
```

Ограничения (`constraints`) и приёмка (`acceptance`) — две разные коллекции и
показываются раздельно: первое про форму решения, второе про результат
(ADR-006). Свести их в один список — значит потерять различие, вокруг которого
строится разговор на зачёте.

Чекпойнт вырожден: у него пустые `misconceptions`, `materials`, `questions`.
Экран обязан свернуться до «Заголовок + Результаты + Практика + Зачёт», а не
показывать шесть пустых секций с заголовками.

## Цикл зачёта

Без сети он выглядит так:

```
[Скопировать промпт]  →  человек вставляет в любой чат
                      →  проходит зачёт
                      →  копирует ответ целиком
[Вставить вердикт]    →  приложение берёт последний JSON-блок
                      →  обновляет статус по протоколу
                      →  открывает разбор
```

Вставляется **весь ответ**, а не выдранный JSON: требовать от человека ручного
выковыривания блока — значит гарантировать ошибки. Парсер сам находит последний
блок (S13).

С настроенным провайдером (S41–S42) тот же цикл идёт внутри приложения. Протокол и
формат вердикта не меняются — меняется только транспорт.

Полные правила «вердикт → статус» — в [protocol.md](../ru/protocol.md).

## Ручное управление

Любой статус можно поставить руками, без зачёта. Это требование, а не уступка:
человек мог пройти тему на работе, знать её заранее, или не согласиться с
моделью. Ручная отметка пишется с `source: manual` и отличается от сданного
зачёта в статистике — иначе цифра «пройдено» перестаёт что-либо значить.

## Клавиатура

Приложение полностью управляется с клавиатуры. Фокус видим всегда. `Esc`
возвращает на уровень вверх. Поиск — по `/`.
