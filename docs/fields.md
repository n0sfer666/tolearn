# Перечень полей бандла

Исчерпывающий список полей, которые описывают [схемы](schemas/). Каждое поле
отнесено ровно к одной роли — иначе DoD «эталон разбирается со всеми полями»
у S03/S04 нечем проверить.

- **рендер** — показывается человеку (в интерфейсе или в промпте экзаменатора) и
  на поведение приложения не влияет.
- **логика** — влияет на статус, порядок, знаменатель, расписание или запуск.
- **игнор** — приложение поле не читает: ни показа, ни счёта, ни ветвления. В
  `progress.yaml` такое поле ещё и переносится при записи дословно, чтобы будущая
  версия протокола нашла его на месте; в файлах бандла переносить нечего —
  приложение в них не пишет.

Роль «логика» сильнее «рендера»: поле, которое влияет на поведение, отмечено как
логика, даже если ещё и показывается. Обратное неверно — «рендер» означает, что
удаление поля не меняет ни одного статуса и ни одного числа.

Путь пишется так же, как его строит гейт схем: `topics[].priority` — поле
элемента массива, `topics.*.status` — поле значения словаря. Контейнеры (массивы
и вложенные объекты) в списке есть: их роль — про сам факт наличия коллекции.
Полнота списка и отсутствие лишних строк проверяются тестом
`every_described_field_is_classified_in_the_field_list`.

## roadmap.yaml

| Поле | Роль | Почему |
|---|---|---|
| `schema` | логика | мажор версии контракта; несовпадение внутри бандла — ошибка целостности |
| `id` | логика | связывает бандл с `progress.roadmap_id` и записью в реестре |
| `title` | рендер | заголовок программы |
| `subject` | рендер | о чём программа |
| `goal` | рендер | наблюдаемый критерий цели |
| `generated_at` | рендер | когда программа сгенерирована |
| `generated_by` | рендер | чем сгенерирована |
| `locale` | логика | язык программы: по нему S56 выбирает язык распознавания речи, а не только подставляет строку в промпт |
| `weekly_hours` | логика | бюджет часов в неделю, из него считаются сроки в сводке |
| `env_constraints` | рендер | ограничения окружения, подставляются в промпт |
| `version_pins` | логика | закреплённые версии: с их значениями сверяется `covers_version` материалов |
| `calibration` | логика | результат калибровки, из него берётся статус `passed_out` |
| `calibration.method` | рендер | чем калибровали |
| `calibration.probed` | рендер | сколько тем прощупали |
| `calibration.passed_out` | логика | единственный источник статуса `passed_out` |
| `calibration.interrupted` | рендер | калибровку прервали, часть тем не прощупана |
| `defaults` | логика | значения по умолчанию для полей темы |
| `defaults.revalidate_after_days` | логика | срок годности знания по классу изменчивости |
| `defaults.revalidate_after_days.stable` | логика | срок для `volatility: stable` |
| `defaults.revalidate_after_days.evolving` | логика | срок для `volatility: evolving` |
| `defaults.revalidate_after_days.volatile` | логика | срок для `volatility: volatile` |
| `stages` | логика | порядок этапов и границы сводки |
| `stages[].n` | логика | номер этапа, по нему темы группируются |
| `stages[].title` | рендер | заголовок этапа |
| `stages[].generated` | логика | тема без файла в несгенерированном этапе — «не сгенерирована», а не потеря |
| `stages[].checkpoint` | логика | чекпойнт этапа; без покрытия этапа — ошибка целостности |
| `topics` | логика | состав программы и знаменатель прогресса |
| `topics[].id` | логика | ключ темы в графе, в прогрессе и в конспектах |
| `topics[].title` | рендер | заголовок темы в списке |
| `topics[].stage` | логика | принадлежность этапу; выход за диапазон — ошибка целостности |
| `topics[].file` | логика | путь к файлу темы внутри бандла |
| `topics[].est_hours` | логика | оценка часов, складывается в сводку по этапу и программе |
| `topics[].priority` | логика | `optional` не входит в знаменатель прогресса, `core` и `recommended` входят |

## topics/*.yaml

| Поле | Роль | Почему |
|---|---|---|
| `schema` | логика | мажор версии контракта темы |
| `id` | логика | должен совпасть с `topics[].id` шапки |
| `title` | рендер | заголовок темы |
| `stage` | логика | дубль этапа в файле темы; расхождение с шапкой — ошибка целостности |
| `depends_on` | логика | граф зависимостей: источник статуса `blocked` и обнаружения циклов |
| `est_hours` | игнор | часы считаются по шапке; в файле темы поле хранится, но не читается |
| `volatility` | логика | выбирает ключ в `defaults.revalidate_after_days` |
| `revalidate_after_days` | логика | перекрывает `defaults`, если есть |
| `verified_at` | логика | база срока годности: из неё выводится `stale_passed`, а при `retention: by_use` — и `next_review_at` |
| `confidence` | рендер | насколько генератор уверен в теме |
| `retention` | логика | выбирает базу отсчёта `next_review_at` и решает, ставится ли дата вообще ([протокол](protocol.md#next_review_at-по-retention)) |
| `version_context` | рендер | какие закреплённые версии важны для темы |
| `outcomes` | рендер | что человек сможет после темы |
| `misconceptions` | рендер | типичные заблуждения, подставляются в промпт |
| `materials` | рендер | список материалов темы; порядок в файле — путь чтения, экран нумерует его как есть и не пересортировывает |
| `materials[].title` | рендер | название материала |
| `materials[].url` | логика | адрес: ключ дедупликации в офлайн-хранилище |
| `materials[].type` | логика | выбирает способ сохранения: `repo` — клон, `video` — отдельный инструмент |
| `materials[].tier` | рендер | насколько материал первоисточник |
| `materials[].lang` | рендер | язык материала |
| `materials[].liveness` | логика | `paywall` и `login_required` останавливают сохранение до попытки |
| `materials[].published` | рендер | дата публикации, `null` — неизвестна |
| `materials[].covers_version` | логика | сверяется со значениями `version_pins`: несовпадение даёт пометку «пин неизвестен» (S51) |
| `materials[].checked_at` | рендер | когда генератор проверил ссылку |
| `materials[].stale` | рендер | отметка «содержание отстало», показывается рядом со ссылкой |
| `materials[].delta` | рендер | в чём именно отстало, показывается вместе с `stale` |
| `materials[].note` | рендер | зачем этот материал в теме; показывается под ссылкой |
| `practice` | рендер | практика темы |
| `practice.kind` | рендер | код, эксплуатация или разбор |
| `practice.tier` | рендер | вес практики |
| `practice.task` | рендер | что сделать |
| `practice.deliverable` | рендер | что должно получиться |
| `practice.starting_point` | рендер | с чего начать, `null` — с нуля |
| `practice.fallback` | рендер | что делать, если застрял |
| `practice.time_box_min` | рендер | сколько времени на практику |
| `practice.smoke_checked` | рендер | показывается перед запуском команды: проверял ли генератор её работоспособность |
| `practice.constraints` | рендер | условия, при которых практика считается сделанной честно |
| `practice.constraints[].id` | логика | ключ пункта: по нему раннер связывает результат запуска с утверждением, и им же записывается `failed_checks` |
| `practice.constraints[].claim` | рендер | что утверждает условие |
| `practice.constraints[].check` | логика | команда для раннера, запускается только по действию человека |
| `practice.constraints[].expect` | рендер | ожидаемый результат команды |
| `practice.acceptance` | рендер | исполняемая приёмка практики |
| `practice.acceptance[].id` | логика | ключ пункта: по нему раннер связывает результат запуска с утверждением, и им же записывается `failed_checks` |
| `practice.acceptance[].claim` | рендер | что утверждает пункт приёмки |
| `practice.acceptance[].check` | логика | команда для раннера, запускается только по действию человека |

## progress.yaml

| Поле | Роль | Почему |
|---|---|---|
| `schema` | логика | мажор версии контракта прогресса |
| `roadmap_id` | логика | к какой программе относится файл |
| `topics` | логика | состояния по темам; порядок ключей при записи стабилен |
| `topics.*.status` | логика | текущий статус темы |
| `topics.*.attempts` | логика | история попыток: три `fail` подряд дают предложение разделить тему |
| `topics.*.attempts[].at` | логика | база отсчёта `retry_after_days` и порядок попыток, по которому считаются три провала подряд |
| `topics.*.attempts[].source` | логика | отличает ручную отметку от зачтённой в статистике |
| `topics.*.attempts[].verdict` | логика | вход таблицы «вердикт → статус» |
| `topics.*.attempts[].model` | рендер | чем принимался экзамен, `null` — вручную |
| `topics.*.attempts[].hinted` | рендер | нужны ли были подсказки |
| `topics.*.attempts[].practice_accepted` | логика | без принятой практики `pass` не выставляется |
| `topics.*.attempts[].failed_checks` | рендер | какие пункты приёмки не прошли |
| `topics.*.attempts[].per_question` | логика | вердикт без него отвергается разбором |
| `topics.*.attempts[].per_question[].id` | логика | к какому вопросу относится ответ |
| `topics.*.attempts[].per_question[].result` | логика | из результатов по вопросам собирается вердикт |
| `topics.*.attempts[].per_question[].quote` | рендер | цитата из ответа, `null` — ответа не было |
| `topics.*.attempts[].per_question[].missed` | рендер | что человек не назвал |
| `topics.*.attempts[].per_question[].signal_extension` | рендер | ответ вышел за ожидаемые признаки |
| `topics.*.attempts[].gaps` | рендер | пробелы, найденные попыткой |
| `topics.*.attempts[].calibration` | рендер | как самооценка соотносится с результатом |
| `topics.*.attempts[].notes` | рендер | замечания экзаменатора |
| `topics.*.attempts[].next_action` | логика | что предложить дальше |
| `topics.*.attempts[].retry_after_days` | логика | через сколько дней повторять; без `next_action` не имеет смысла |
| `topics.*.attempts[].raw` | игнор | исходный текст вердикта: хранится дословно, чтобы будущая версия протокола пересобрала историю |
| `topics.*.passed_at` | логика | база `next_review_at` при `retention: by_schedule` ([протокол](protocol.md#next_review_at-по-retention)) |
| `topics.*.next_review_at` | логика | срок следующего возврата к теме; очередь повторений строится по нему |
| `topics.*.gaps` | рендер | накопленные пробелы по теме |
| `topics.*.practice` | логика | запись практики: сколько времени заняла и истёк ли таймбокс; отдельно от `attempts[]`, потому что попытка появляется только по вердикту, а таймбокс истекает раньше |
| `topics.*.practice.started_at` | логика | момент запуска отсчёта, `null` — таймер на паузе; отсчёт восстанавливается от него после перехода между экранами |
| `topics.*.practice.spent_sec` | логика | накопленное время практики, не считая текущего запуска |
| `topics.*.practice.expired` | рендер | таймбокс уже истекал; истечение ничего не блокирует |
