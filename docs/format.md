# Формат программы v2

Справочник полей программы v2 и её этапов. Форму описывают две схемы:
[`tolearn/program/1`](schemas/program.schema.json) и
[`tolearn/stage/1`](schemas/stage.schema.json). Эталон —
[`examples/chiptune/`](../examples/chiptune/), корпус фикстур —
[`fixtures/v2/`](../fixtures/v2/). Почему формат такой —
[ADR-020](adr/020-v2-program-library.md).

```
<uuid>/
  program.yaml        цель, уровень, карта, источники, контекст генерации
  stages/<id>.yaml    этап листа: блоки, практика, вопросы зачёта
  assets/             SVG и картинки, на которые ссылаются блоки
  children/<uuid>/    подпрограмма — такой же каталог
```

Узел держит подпрограммы (`map.children`), лист — этапы (`map.stages`), глубина
дерева — не больше трёх уровней. У листа файл `stages/<id>.yaml` появляется,
когда этап сгенерирован: строка карты без файла — этап, которого ещё нет.

## Блоки

Текст этапа — список блоков `{id, kind, text}`. `text` — Markdown для
`paragraph`, `heading` и `callout`, исходник для `code`, Mermaid для `diagram`
и подпись для `image`.

| `kind` | Поля кроме `id`, `kind`, `text` |
|---|---|
| `paragraph` | — |
| `heading` | — |
| `callout` | — |
| `code` | `lang` — язык подсветки |
| `diagram` | `asset` — готовая SVG-схема; Mermaid в `text` — её исходник |
| `image` | `asset`, `license`, `attribution`; `source` — откуда картинка, если не своя |

`id` блока — первые восемь шестнадцатеричных знаков хэша его текста
(`tolearn_core::block::id`, S97). Повтор текста внутри этапа получает суффикс по
порядку появления: `27e110c4`, затем `27e110c4-2`. Блоки этапа и блоки задания
практики (`practice.task`) — одна последовательность: общий текст в `blocks` и
в `task` даёт суффикс так же, как повтор внутри `blocks`.

## Что ловит схема, а что — чтение

Схема проверяет форму одного документа: обязательные поля, закрытые объекты,
типы, шаблоны `uuid`, `slug`, `id` и путей ассетов, длины строк, даты, диапазон
часов из двух чисел не меньше единицы. Каждое её правило пинит битая фикстура в
`fixtures/v2/broken/`.

Связи между значениями и файлами схема не выражает — их проверяет чтение
программы (S99), и документы, которые схема принимает, а чтение обязано
отвергнуть, лежат в `fixtures/v2/strict/`:

- `id` блока совпадает с S97 от его текста;
- поля блока соответствуют `kind` по таблице выше; у `image` есть `license` и
  `attribution`;
- файл из `asset` лежит в `assets/` той же программы;
- у часов `min ≤ max`;
- у узла нет этапов, у листа нет подпрограмм; глубина ≤ 3; UUID в дереве
  уникальны, и `map.children[].uuid` совпадает с каталогом `children/<uuid>/`.

## Роли и пути

Роли те же, что у v1 ([fields.md](fields.md)): **рендер** показывается человеку
или уходит в промпт и на поведение не влияет, **логика** влияет на статус,
порядок, знаменатель или запуск, **игнор** не читается. Путь пишется так, как
его строит гейт схем: `map.stages[].hours` — поле элемента массива. Полноту
таблиц проверяет `every_described_field_is_classified_in_the_field_list`.

## program.yaml

| Поле | Роль | Почему |
|---|---|---|
| `schema` | логика | мажор версии контракта; чужой мажор — отказ чтения |
| `uuid` | логика | имя каталога программы и ключ её состояния в `<data>/state/<uuid>/` |
| `slug` | рендер | читаемое имя для человека; программу опознаёт `uuid` |
| `title` | рендер | название программы |
| `goal` | рендер | наблюдаемый критерий цели; уходит в промпт генерации |
| `level` | рендер | стартовый уровень человека; уходит в промпт генерации |
| `generation` | логика | контекст, с которым генерируются следующие этапы |
| `generation.locale` | логика | язык программы: на нём генерируются этапы и по нему выбирается язык распознавания речи |
| `generation.volatility` | логика | выбирает, какие источники предлагает модель: учебник или страницы ([ADR-014](adr/014-model-text-app-verified-sources.md)) |
| `generation.request` | рендер | исходный запрос человека; уходит в промпт генерации |
| `map` | логика | дерево программы |
| `map.stages` | логика | этапы листа по порядку; знаменатель прогресса |
| `map.stages[].id` | логика | связывает строку карты с `stages/<id>.yaml` и прогрессом этапа |
| `map.stages[].title` | рендер | название этапа в карте, пока этап не сгенерирован |
| `map.stages[].hours` | логика | диапазон часов `[min, max]`, складывается в сводку по программе |
| `map.children` | логика | подпрограммы узла по порядку |
| `map.children[].uuid` | логика | связывает строку карты с каталогом `children/<uuid>/` |
| `map.children[].title` | рендер | название подпрограммы в карте |
| `map.children[].hours` | логика | диапазон часов подпрограммы, складывается в сводку родителя |
| `sources` | рендер | проверенные приложением источники программы |
| `sources.books` | рендер | учебники |
| `sources.books[].title` | рендер | название книги |
| `sources.books[].authors` | рендер | авторы |
| `sources.books[].isbn` | рендер | ISBN-13, по нему приложение проверило книгу |
| `sources.books[].chapter` | рендер | глава, на которую опирается программа |
| `sources.books[].checked_at` | рендер | когда приложение проверило книгу |
| `sources.pages` | рендер | веб-страницы |
| `sources.pages[].title` | рендер | заголовок страницы |
| `sources.pages[].url` | рендер | адрес страницы |
| `sources.pages[].checked_at` | рендер | когда приложение проверило страницу |

## stages/*.yaml

| Поле | Роль | Почему |
|---|---|---|
| `schema` | логика | мажор версии контракта; чужой мажор — отказ чтения |
| `id` | логика | совпадает с `map.stages[].id` и именем файла |
| `title` | рендер | название этапа |
| `blocks` | рендер | текст этапа по порядку |
| `blocks[].id` | логика | адрес блока: к нему привязаны уточнения и ответы в `<data>/state/<uuid>/` |
| `blocks[].kind` | логика | выбирает, как блок рисуется и какие поля у него обязательны |
| `blocks[].text` | рендер | содержимое блока |
| `blocks[].lang` | рендер | язык подсветки кода |
| `blocks[].asset` | рендер | файл схемы или картинки в `assets/` |
| `blocks[].license` | рендер | лицензия картинки |
| `blocks[].attribution` | рендер | автор картинки |
| `blocks[].source` | рендер | откуда взята картинка |
| `practice` | логика | практика этапа; без принятой практики этап не пройден |
| `practice.task` | рендер | задание блоками |
| `practice.task[].id` | логика | адрес блока задания, общая последовательность с `blocks` |
| `practice.task[].kind` | логика | как рисуется блок задания |
| `practice.task[].text` | рендер | содержимое блока задания |
| `practice.task[].lang` | рендер | язык подсветки кода в задании |
| `practice.task[].asset` | рендер | файл схемы или картинки задания |
| `practice.task[].license` | рендер | лицензия картинки задания |
| `practice.task[].attribution` | рендер | автор картинки задания |
| `practice.task[].source` | рендер | откуда взята картинка задания |
| `practice.deliverable` | рендер | что человек сдаёт |
| `practice.constraints` | рендер | ограничения на решение |
| `practice.constraints[].id` | логика | адрес ограничения в отметках человека |
| `practice.constraints[].claim` | рендер | что должно выполняться |
| `practice.constraints[].check` | логика | команда проверки; запускается только по действию человека |
| `practice.constraints[].expect` | рендер | каким должен быть результат проверки |
| `practice.acceptance` | логика | критерии приёмки: практика принята, когда отмечены все |
| `practice.acceptance[].id` | логика | адрес критерия в отметках человека |
| `practice.acceptance[].claim` | рендер | что должно выполняться |
| `practice.acceptance[].check` | логика | команда проверки; запускается только по действию человека |
| `practice.acceptance[].expect` | рендер | каким должен быть результат проверки |
| `questions` | логика | вопросы зачёта; зачёт сдан, когда приняты ответы на все |
| `questions[].id` | логика | адрес вопроса, к нему привязан ответ человека |
| `questions[].text` | рендер | вопрос |
| `questions[].answer` | рендер | эталонный ответ; уходит в промпт экзаменатора |
