# Ручные тест-кейсы

Здесь лежит только то, чего **не берут автотесты**: живая модель и CLI-харнесс,
системное хранилище ключей, настоящая файловая система, сеть, долгие прогоны и
поведение экрана во времени. Всё, что проверяется на фикстурах без сети, живёт в
`cargo test` и `pnpm -C ui test` и сюда не дублируется.

## Как запускать приложение

```sh
pnpm -C ui install
pnpm -C ui build
cargo run -p tolearn-app --release --bin tolearn-desktop
```

Дальше «запустить приложение» в шагах означает именно это (или запуск готового
`target/release/tolearn-desktop`).

## Соглашения

- Один тест-кейс — один файл. Связанное проверяется в одном файле ветками.
- Шаги нумеруются; ожидаемый результат пишется после блока шагов как `ОР:`.
- Ветка сценария — свой блок шагов со своим `ОР:`.
- Кейс не трогает то, что уже закрыто автотестом, — только наблюдаемое поведение
  на живом окружении.

## Состояние перед прогоном

Если нужно чистое состояние, каталоги приложения удаляются целиком:

```sh
rm -rf ~/.config/tolearn ~/.local/share/tolearn
```

На macOS ключи провайдера и ключ устройства живут в связке ключей: записи
`tolearn` в Keychain Access удаляются отдельно.

Эталонная программа для импорта — `examples/chiptune`, собранная в пакет
`tolearn pack` (шаги — в [bundle/01-import.md](bundle/01-import.md)).
