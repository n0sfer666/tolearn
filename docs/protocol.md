# Протокол зачёта

Контракт приложения. Здесь описано, что `tolearn` делает с вердиктом.

Почему это лежит в репозитории, а не в бандле: `examiner.md` внутри бандла —
файл, который перегенерирует LLM и может отредактировать пользователь. Он
описывает, что делает **экзаменующая модель**. Что делает **приложение** —
решает приложение, иначе поведение трекера зависит от содержимого импортированной
папки. Расхождение между этим документом и `examiner.md` бандла разрешается в
пользу этого документа; приложение показывает предупреждение при импорте, если
хвост `examiner.md` описывает другие правила.

## Граница промпта

`examiner.md` состоит из двух частей, разделённых горизонтальной чертой `---`:

- **до `---`** — промпт для экзаменующей модели. Только он копируется;
- **после `---`** — разделы «Что трекер делает с результатом» и «Известное
  ограничение». Это адресовано трекеру и человеку и в промпт не попадает.

Заголовочный блок в начале файла (пометка «копируется в бандл как examiner.md»)
тоже вырезается: он адресован генератору.

## Вердикт

Ответ модели заканчивается ровно одним JSON-блоком. Приложение берёт
**последний** блок из вставленного текста — вставляется весь ответ целиком,
требовать от человека выковыривать блок вручную значит гарантировать ошибки.

```json
{
  "topic_id": "...",
  "date": "YYYY-MM-DD",
  "model": "...",
  "verdict": "pass|partial|fail|blocked",
  "hinted": false,
  "practice_accepted": true,
  "failed_checks": [],
  "per_question": [
    {"id": "q1", "result": "ok|partial|miss", "quote": "...",
     "missed": [], "signal_extension": false}
  ],
  "gaps": ["..."],
  "calibration": "...",
  "notes": ["..."],
  "next_action": "proceed|retry_failed|redo_practice|split_topic",
  "retry_after_days": 3
}
```

Обязательны: `topic_id`, `verdict`, `per_question`. Вердикт без `per_question`
отвергается — без разбора по вопросам он ничем не отличается от оценки на глаз.
`topic_id`, не совпадающий с открытой темой, отвергается с явным сообщением: это
почти всегда вставка ответа не в ту тему.

При остальных недостающих полях разбор частичный: применяется то, что есть, и
показывается список того, чего не хватило.

## Вердикт → статус

| Вердикт | Статус | Дополнительно |
|---|---|---|
| `pass` | `passed` | `passed_at` = дата; `next_review_at` по `retention` |
| `partial` | `in_progress` | в очередь только вопросы с `result != ok`; повтор через `retry_after_days` |
| `fail` | `failed` | `gaps[]` подсвечены на экране разбора, практика переделывается |
| `blocked` | `in_progress` | **попытка не пишется в статистику** |

`blocked` означает, что зачёт не состоялся: требуемый артефакт не предъявлен.
Это не результат, поэтому он не участвует ни в счётчике попыток, ни в подсчёте
трёх провалов подряд.

## Три провала подряд

Три `fail` подряд по одной теме — сигнал, что тема слишком крупная или не
выполнена предпосылка. Приложение показывает предложение разделить тему и даёт
готовый текст запроса на перегенерацию в режиме `refresh`. Само оно бандл не
меняет.

## Ручная отметка

Любой статус ставится вручную, без зачёта: человек мог знать тему заранее,
пройти её на работе или не согласиться с моделью. Ручная отметка записывается с
признаком `source: manual` и отличается от сданного зачёта в статистике — иначе
цифра «пройдено» перестаёт что-либо значить.

Обратное тоже верно: ручной сброс статуса не стирает историю попыток.

## Форма попытки

Элемент `attempts[]` в `progress.yaml` хранит вердикт дословно плюс то, что
знает приложение, а не модель:

```yaml
attempts:
  - at: "2026-07-26T18:40:00+03:00"
    source: exam            # exam | manual
    verdict: partial
    model: "..."
    hinted: false
    practice_accepted: true
    failed_checks: []
    per_question: [...]
    gaps: [...]
    calibration: "..."
    notes: [...]
    next_action: retry_failed
    retry_after_days: 3
    raw: |                  # исходный JSON-блок как пришёл
      {...}
```

`raw` хранится всегда. Формат вердикта может измениться в следующей версии
протокола, и исходный текст — единственное, из чего можно будет пересобрать
историю.

## Известное ограничение

Промпт снижает поддакивание, но не устраняет его. Реально держит оценку только
исполняемая приёмка практики; для теоретических тем `pass` остаётся суждением
модели. Приложение это не исправляет и не делает вид, что исправляет — оно лишь
не даёт пропустить шаги протокола.
