# Фикстуры

Эталонный бандл [`examples/llm-agents-base/`](../examples/llm-agents-base/) —
главная фикстура и главный источник правды по форме. Он не меняется: любая
ветка, которой в нём нет, добавляется сюда, а не подкручивается в эталоне.

```
valid/{roadmap,topic,progress}/    документы, которые схема обязана принять
broken/{roadmap,topic,progress}/   документы, которые схема обязана отвергнуть
```

## valid/

Валидные фикстуры покрывают то, чего в эталоне нет: цикл зависимостей
(`cycle-a` ↔ `cycle-b`), собственный срок ревалидации темы против `defaults`
шапки (`stale-knowledge`), материалы за `paywall` и `login_required`, `video`,
все девять значений `type` и `tier: T3` (`offline-edge`), типы вопроса, которых
нет в остальных темах (`question-shapes`), историю попыток с обоими значениями
`source` и всеми вердиктами (`progress/attempts-history.yaml`).

`topic/offline-edge.yaml` длиннее 200 строк: исчерпывающее перечисление девяти
значений `type` и есть его содержание, а разрез по этому перечислению превратил
бы одну проверку в блуждание по файлам. Всё, у чего нашлась своя граница смысла,
из него уже вынесено — так появился `question-shapes`.

Три программы, к которым относятся документы: `minimal-program` — обязательный
минимум формы, `corpus-program` — ветки выше, `llm-agents-base` — эталон.
`progress/attempts-history.yaml` описывает прогресс по эталонной программе, и
его ключи тем — настоящие `id` из эталона.

`id` темы уникален по **всему** валидному корпусу, а не внутри программы: граф
зависимостей гейт строит один раз по всем темам сразу и разделяет программы
только областью обхода, поэтому одинаковый `id` в двух программах склеил бы две
разные темы в одну вершину. Гейт это проверяет и называет занятый `id`.

`valid/` — раскладка **по видам документа, а не по бандлу**: это корпус для схем,
и папкой бандла он не является. Поэтому `topics[].file` внутри фикстур
(`topics/cycle-a.yaml`) указывает на путь, которого здесь нет: он про будущий
бандл, а не про эту папку. Собранному бандлу место в `examples/`.

Даты `next_review_at` посчитаны по правилу из
[protocol.md](../docs/protocol.md#next_review_at-по-retention), и корпус
показывает обе базы: `by_schedule` считает от `passed_at`
(`stale-knowledge`: `2026-06-01 + 30`), `by_use` — от `verified_at` темы
(`local-runtime`: `2026-07-26 + 90`, `offline-edge`: `2026-07-20 + 90`).

Гейт `every_fixed_value_appears_in_the_valid_corpus` требует, чтобы каждое
значение из каждого `enum` и `const` всех трёх схем встречалось в валидном
корпусе. Добавили значение в схему — добавьте документ, который его несёт.

## broken/

Имя файла — `<код>__<что сломано>.yaml`, где код — нарушенное ключевое слово
JSON Schema. Фикстура обязана давать **ровно одну** ошибку — тест сравнивает
список кодов валидатора со списком из одного элемента, заявленного в имени. Поэтому
битая фикстура — это полная копия валидного документа с одной правкой: любое
второе расхождение со схемой сломало бы «ровно одну ошибку».

Отсюда похожие файлы на диске, и это не пропущенная абстракция. Генерировать их
в тесте нельзя: с S17 по этим же файлам гоняется бинарник `tolearn validate`,
которому нужен путь, а не значение в памяти. Базовые документы, от которых сняты
копии, — `valid/roadmap/minimal.yaml`, `valid/topic/minimal-topic.yaml`,
`valid/topic/stale-knowledge.yaml` и `valid/progress/minimal.yaml`; правка схемы,
меняющая базу, требует правки копий: гейт «ровно одна ошибка» падает именно на
той копии, которая отстала, и называет её путь.

Код в имени — тот, который выдаёт валидатор, а не тот, который логичнее. Ключ
словаря, не прошедший `propertyNames`, отвергается с кодом `pattern` — отсюда
`pattern__version-pin-name-in-caps.yaml` рядом с `pattern__roadmap-id-not-a-slug.yaml`.

Пол — двенадцать **разных** кодов, сейчас их пятнадцать на семнадцати фикстурах.
Каждый из трёх видов документа несёт хотя бы одну битую фикстуру.
